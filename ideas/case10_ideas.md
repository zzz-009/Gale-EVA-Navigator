# Case 10: Interplanetary Survival Guide: Martian Map — アプリ提案

> **テーマ要約**: 火星を歩く最初の宇宙飛行士のために、複数のNASAミッションのデータを重ね合わせた**超局所的（hyperlocal）な地図・ツール**をつくる。ルート計画、現在の状況、安全情報、科学目標を1つにまとめ、「Marswalk（火星の船外活動）」を成功させる。
> **ポイント**: ①科学目標と場所をまず決める（例: Curiosity が2025年に調べた Mount Sharp のボックスワーク構造） ②3種類以上のデータ（光学、熱、分光、地形、大気、放射線、化学など）を重ねる ③安全が最優先（放射線、宇宙服での移動の制約、障害物の回避） ④表示形式は自由（居住施設内のディスプレイ、タブレット、ヘルメットのHUD）
> **既存ツールとの違い**: JPL Mars Trek などは地域・全球の表示向け。今回は**1回の船外活動で歩く範囲**に絞った表示が求められている

---

## 案1: EVA Route Planner — 傾斜・岩・距離から「歩けるルート」を自動計画

- **コンセプト**: 出発地（居住施設やローバー）と科学目標地点を選ぶと、地形データから**宇宙服で歩ける傾斜・岩の少ないルート**を自動計算。所要時間、消費する酸素・電力の見積もり、途中の観測ポイントを含めたEVA計画書を出力する。
- **主な機能**
  - HiRISE DTM（数m解像度の地形）から傾斜マップを作成し、通行コストを計算（A* 探索）
  - 岩の多さ（HiRISE 画像からの岩石密度や熱慣性）を障害物コストに反映
  - 「傾斜◯度以上は避ける」「総距離◯km以内」などの制約をスライダーで設定（宇宙服の能力は仮定値として明示）
  - ルート上の観測ポイント（ボックスワーク、層状堆積物など）と、各地点で行う科学作業
  - 帰還可能地点（引き返し点）の表示
- **使用データ**: HiRISE（画像・DTM）、CTX、MOLA、THEMIS（熱慣性）、Curiosity のナビゲーションカメラ画像
- **技術スタック例**: Python（rasterio, scikit-image, networkx で経路探索）、MapLibre / CesiumJS
- **差別化ポイント**: 課題文の「障害物を避けるルートマップ」を、地形データから計算で導く。数値の根拠が明確
- **MVP範囲（2日）**: Mount Sharp（Gale クレーター）の HiRISE DTM 1枚の範囲で、ルート3本の比較
- **リスク・注意点**: HiRISE DTM は大容量。対象範囲を切り出して前処理しておく

## 案2: Helmet HUD Prototype — ヘルメットのバイザーに映る「歩きながら見る地図」

- **コンセプト**: 宇宙飛行士がヘルメットのバイザー越しに見る**HUD（ヘッドアップディスプレイ）**を、Webでプロトタイプ化。進行方向の矢印、次の目標までの距離、酸素残量、放射線量、帰還までの残り時間、警告を、視界を邪魔しない最小限の表示で出す。
- **主な機能**
  - Curiosity / Perseverance の実際の地表画像を背景にしたHUD表示
  - 「次の観測ポイントまで残り120m、北東」のナビ表示
  - 状態に応じた表示切替（移動中 / 観測中 / 緊急時）
  - 音声読み上げ（グローブで操作しにくいことを想定した音声操作）
  - 宇宙天気（太陽フレア警報）による「すぐ戻れ」警告
- **使用データ**: Mars 2020 / MSL の地表画像（Navcam、Mastcam-Z）、DONKI、Curiosity RAD、REMS / MEDA の気象データ
- **技術スタック例**: Three.js / A-Frame（WebXR 対応）、Web Speech API
- **差別化ポイント**: 課題文が例示したHUD形式を体験できるデモ。審査員がVRゴーグルで見られるとインパクト大
- **MVP範囲（2日）**: 1ルートの疑似歩行（画像の切り替え）+ HUD 3モード
- **リスク・注意点**: 見た目に寄りすぎないよう、表示している値の出典（どのデータか）を説明ページで示す

## 案3: Layered Science Map — 6種類のデータを重ねて「どこで何を調べるか」を決める

- **コンセプト**: 1回の船外活動の範囲（数km四方）に、**光学画像・地形・熱慣性・鉱物組成・放射線・気象**のレイヤーを重ねられる地図。レイヤーの組み合わせから「粘土鉱物があり、かつ平坦で近い場所」などの条件で科学ターゲットを絞り込む。
- **主な機能**
  - レイヤー: HiRISE（光学）、HiRISE DTM（地形）、THEMIS（熱慣性）、CRISM（鉱物）、Curiosity RAD（放射線）、REMS（気温・気圧）
  - 条件フィルター（例: 「含水鉱物あり」AND「傾斜10度未満」AND「居住施設から2km以内」）
  - 透明度スライダーと、2レイヤー比較スワイプ
  - 地点をクリックすると、その場所の探査車の画像（地上から見た景色）を表示
- **使用データ**: HiRISE、CTX、CRISM、THEMIS、MOLA、Curiosity の RAD / REMS / ChemCam のデータ
- **技術スタック例**: MapLibre（火星座標系のタイル）、Mars Trek の WMTS タイル、Python 前処理
- **差別化ポイント**: 「3種類以上のデータを重ねる」要件を大きく超え、科学的な場所選びのツールとして成立させる
- **MVP範囲（2日）**: Gale クレーターの1エリア × レイヤー4種
- **リスク・注意点**: データごとに解像度が大きく違う（CRISM は約18m、HiRISE は約25cm）。表示時に解像度を明記

## 案4: Buddy EVA Planner — 2人1組 + ローバーの作業分担を計画するツール

- **コンセプト**: 課題文の「2人1組で作業する」「ローバーで道具を運ぶ」を前提に、2人の宇宙飛行士とローバーの**動きと作業をタイムラインで計画**する。お互いが見える範囲にいるか、ローバーに戻れる距離か、通信が届くかを自動チェック。
- **主な機能**
  - 地図上で2人とローバーのルートを別々に設定
  - ガントチャート型のタイムライン（移動・観測・サンプル採取・休憩）
  - 安全チェック: 2人の距離、見通し（地形による視線の遮り）、ローバーまでの帰還時間
  - 酸素・電力・持ち運ぶ機材の重さ（火星重力は地球の約38%）の管理
- **使用データ**: HiRISE DTM（見通し計算）、MOLA、火星の重力・気象データ
- **技術スタック例**: React + vis-timeline、Python（視線計算）、MapLibre
- **差別化ポイント**: 地図に「チーム運用」の視点を加え、人間が行くからこそ必要な計画を扱う
- **MVP範囲（2日）**: 2人 + ローバー1台、作業タスク6つのシナリオ1本
- **リスク・注意点**: 機能が多いので、まずは「見通しと帰還時間」の2チェックに絞る

## 案5: Mars Field Guide — 現地で見つけた岩を「これは何？」と調べるフィールド図鑑

- **コンセプト**: 地質学者がフィールドで使う図鑑のように、船外活動中に見つけた地形・岩石を**カメラ画像から推定して解説**するタブレットアプリ。Curiosity / Perseverance が実際に観察した地形（ボックスワーク、層状の堆積岩、砂紋など）の事例と照らし合わせ、「採取すべきか」の判断を助ける。
- **主な機能**
  - 写真を撮る → 画像分類で地形タイプを推定（探査車の画像で学習）
  - 類似した過去の観察例と、そのときの科学的発見の表示
  - 現在地の鉱物データ（CRISM）と照合し、採取優先度を提示
  - 観察ノート（音声メモ、位置情報付き）
- **使用データ**: Curiosity / Perseverance の画像（PDS、Mars Raw Images）、NASA の火星地形分類用データセット、CRISM
- **技術スタック例**: TensorFlow.js / ONNX（画像分類をオフラインで実行）、React Native / PWA
- **差別化ポイント**: 課題文の「人間の批判的思考を活かし、その場で科学的な判断をする」を支援する
- **MVP範囲（2日）**: 地形タイプ5種の分類 + 図鑑ページ
- **リスク・注意点**: 分類精度に限界があるため、「最終判断は宇宙飛行士・地上の科学チーム」と明記
