## 案1: Horizon Panorama — 着陸地点に立った視点で、太陽と地球がどこを通るかを見せる

- **課題文の項目**: 太陽・地球の位置を地平線と一緒に表示 / 複数の見せ方 / 地形と月の丸みで決まる地平線
- **コンセプト**: 横軸が方位 0〜360°、縦軸が仰角のパノラマ。LOLA の地形から計算した地平線の輪郭の上に、太陽と地球の通り道を重ねる。**南極では太陽が地平線すれすれを一周し、山に隠れたり出たりする**様子が一目でわかる。
- **データ**: LOLA DEM（地平線）、Horizons（方位・仰角）
- **見どころ**: 縦軸を ±5° に拡大すると、「地平線から 1.5° しか昇らない太陽」が劇的に見える
- **1日実現性**: ◎（v2 の T-12 + T-21）

## 案2: Site × Date Compare Board — 「地点 × 日時」を最大4つ並べて比べる

- **課題文の項目**: 地点の選択と並べての比較 / 日時の選択 / 素早い比較
- **コンセプト**: 有名な地点の一覧（Apollo、南極の CLPS・Artemis 候補、Chandrayaan-3、嫦娥4号）から選び、横に並べる。各カードには小さいパノラマ、太陽高度、日没まで、地球が沈むまで、日照率、地球が見える割合を表示。
- **データ**: Moon Trek（地点を打つ地図）、Horizons、LOLA
- **見どころ**: 南極・赤道（Apollo 11）・裏側（嫦娥4号: 地球が一度も見えない）を並べると、月面の環境の違いが一瞬でわかる
- **1日実現性**: ◎（v2 の T-30〜T-32）

## 案3: Slip Calendar — 着陸日が延びたら、前後90日のどの日が良いかを色で示す

- **課題文の項目**: 日程変更への素早い対応（Background の第3段落、Engagement）/ 月の日・季節による変化
- **コンセプト**: 基準の着陸日の前後90日を、毎日「良 / 注意 / 不可」で塗り分ける。クリックするとその日のパノラマと指標に切り替わる。「7日延期すると日照率が 62% → 31%」のように差も出す。
- **データ**: Horizons（約8か月分）、LOLA
- **見どころ**: **課題文の背景で一番強調されている場面**にそのまま答える。延期の連絡が来た → 数秒で代わりの日が見つかる、というストーリーで発表を締められる
- **1日実現性**: ◯（v2 の T-40）

## 案4: Ops Countdown — 「日没まで」「地球が沈むまで」を運用画面として大きく見せる

- **課題文の項目**: 日没・地球が沈むまでの時間 / 太陽高度を目立たせる / 発電と通信の時間帯
- **コンセプト**: 管制室の画面のように、**残り時間のカウントダウン**と、今後14日間の「発電できる / 通信できる / 両方できる」の帯（ガントチャート）を表示する。両方できる時間が短い日は赤く光る。
- **データ**: Horizons、LOLA
- **見どころ**: 計画者向けの「速さ」を最も直感的に示せる
- **1日実現性**: ◎（v2 の T-22 + T-23）

## 案5: Neighbor Explorer — 「10 km 動くと何が変わる？」を周辺のヒートマップで見せる

- **課題文の項目**: 小さな場所の違いがなぜ大きく効くか / 同じ地域の代わりの地点
- **コンセプト**: 選んだ南極の地点の周り（例: 20 km 四方）について、500 m 間隔の点ごとに日照率と地球が見える割合を計算し、Moon Trek の南極の画像の上にヒートマップで重ねる。クリックした点がそのまま比較ボードに加わる。
- **データ**: Moon Trek（南極タイル）、LOLA、Horizons
- **見どころ**: 「尾根の上は日照率 80%、500 m 下の斜面は 20%」のような極端な差が地図で見える
- **1日実現性**: △（周辺の約1600点の地平線計算が重い。点を 20×20 に減らせば ◯）

## 案6: Earth Sky vs Moon Sky — 地球の空と比べて、月の南極の異常さを伝える

- **課題文の項目**: 専門家にも一般の人にも使える / 月と地球の違いを分かりやすく
- **コンセプト**: 同じ日に「東京の空」と「月の南極の空」のパノラマを上下に並べる。地球では太陽は毎日昇って沈むが、月の南極では約29.5日かけて地平線すれすれを一周し、地球はほぼ同じ方向で上下に揺れるだけ。初心者モードでは用語の説明を表示する。
- **データ**: Horizons（地球上の地点も同じ API で取れる）、LOLA
- **見どころ**: 教育・一般向けの入口になり、発表の「つかみ」に使える
- **1日実現性**: ◎（v2 の T-42。案1の描画を使い回せる）

## 案7: Science × Engineering Scorecard — 地質と永久影から「科学的価値」、日照と通信から「工学的成立性」を並べる

- **課題文の項目**: 科学チームと工学チームの調整（Engagement）
- **コンセプト**: 各地点について、科学側の指標（**USGS の月の統合地質図**の地質単位、永久影（PSR）までの距離）と、工学側の指標（日照率、地球が見える割合）を2軸の散布図に置く。両方が良い地点（右上）がどこかを示す。
- **データ**: USGS 統合地質図、LROC の PSR の範囲、Horizons、LOLA
- **見どころ**: 与えられた USGS 地質図の考え方を、月でそのまま活かせる
- **注意**: 全球の地質図は解像度が粗い。**「地域の特徴の目安」として使い、細かい地点の判定には使わない**と明記する
- **1日実現性**: ◯（地質図の入手方法の確認が先）

## 案8: Lunar Day Player — 月の1日（約29.5日）と季節を早送りで再生する

- **課題文の項目**: 時間変化（アニメーション・タイムライン）/ 季節による変化
- **コンセプト**: 再生ボタンで、パノラマの太陽と地球が動き、タイムラインの帯が進む。「12月」と「6月」を切り替えると、月の自転軸のわずかな傾き（約1.5°）でも南極の日照が大きく変わることがわかる。
- **データ**: Horizons、LOLA
- **見どころ**: 動きがあるのでデモ動画で映える
- **1日実現性**: ◎（v2 の T-25。案1のデータに再生機能を足すだけ）

## 案9: Power & Comm Budget — 太陽電池とバッテリーの設定から「何日生き残れるか」を出す

- **課題文の項目**: 発電と通信の評価
- **コンセプト**: 南極では太陽が低いので、**太陽電池パネルは垂直に立てる**のが前提になる。パネルの向き・面積、バッテリー容量、消費電力を入力すると、太陽の仰角と方位から発電量を計算し、バッテリー残量の推移と「何日目に電力が尽きるか」を出す。地球が見える時間から、送れるデータ量も出す。
- **データ**: Horizons、LOLA
- **見どころ**: 計画者が本当に知りたい「成立するか」に変換できる
- **注意**: 電力モデルは簡易な式であることを明記する（凝りすぎない）
- **1日実現性**: ◯

## 案10: Post-Landing Traverse — 着陸後の探査ルートを、日照・通信・地形・科学的価値で選ぶ

- **課題文の項目**: （課題文の直接の要求ではない）差別化 / 科学チームと工学チームの調整
- **コンセプト**: 南極の1地域で、着陸地点から目標（PSR の縁）までのルートを A* で3通り（最短 / 最安全 / 科学最大）計算する。区間ごとに「なぜこの道か」を説明する。**与えられた Curiosity のルート画像の見せ方**（調査地域の色分け、ルートの線、地域名のラベル）を参考に UI を作る。
- **データ**: LOLA（傾斜・粗さ）、Moon Trek（背景）、PSR、Horizons
- **見どころ**: 他チームとの差別化。ユーザーの「3軸で比べて理由を説明する」という方針を活かせる
- **注意**: 課題文に「ルート」という言葉はない。**本題（案1〜4）が完成してから**の追加機能にする
- **1日実現性**: △（v2 の T-50、P2）
