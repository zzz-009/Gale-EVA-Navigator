# Case 4: Health Monitoring Software — アプリ提案

> **テーマ要約**: 長期ミッション中の宇宙飛行士が、自分の健康指標（血圧、心拍、血糖、体温、睡眠、気分など）を記録・評価し、対処できる**ビジュアルな健康モニタリングソフト**をつくる。
> **背景**: NASA Human Research Program の「宇宙飛行の5つのハザード」= 放射線 / 孤立・閉鎖 / 地球からの距離 / 重力の変化 / 閉鎖環境の有害性。これにより免疫変化、骨量減少、心血管イベント、栄養不足、行動健康の問題などが起こりうる。
> **評価されそうな点**: UIのわかりやすさ（色分け、人体図、グラフ）、測定方法の説明、地上の医師（フライトサージャン）へ相談すべきタイミングの提示、ゲーミフィケーション

---

## 案1: Body Map Console — クリックできる人体図で全身の状態を一目で把握

- **コンセプト**: 画面中央に人体図。心臓・骨・脳・目・免疫系などの部位が**緑/黄/赤**で色分けされ、クリックするとその部位の指標、宇宙での変化の仕組み、推奨アクションが表示される。課題文の例示そのものを、完成度高く作り込む。
- **主な機能**
  - 部位別ステータス（例: 骨 → 運動ログと経過日数から骨量減少リスク、目 → 視力変化の自己チェック）
  - 指標ごとの時系列グラフ（ミッション開始からの推移）
  - 閾値を超えたら「クルー内で対応」「地上のフライトサージャンに相談」の2段階アラート
  - 各指標の「測り方ガイド」（血圧計の使い方、測定タイミング）
  - ハザード（RIDGE）と各部位のつながりを示す解説ビュー
- **使用データ**: NASA Human Research Program の公開資料、NASA Twins Study 等の公開知見、他宇宙機関（ESA/JAXA）の健康管理資料
- **技術スタック例**: React + SVG人体図（アニメーション）、Recharts、ローカルストレージ or IndexedDB（オフライン前提）
- **差別化ポイント**: 地球との通信が遅延・断絶する前提で**完全オフライン動作**を設計思想として打ち出す
- **MVP範囲（2日）**: 6指標（血圧、心拍、血糖、体温、睡眠、気分）+ 部位5か所 + ダミー宇宙飛行士の30日分データ
- **リスク・注意点**: 医療判断を下すように見せない。「これは参考情報であり、診断ではない」の明示と、閾値の出典を表示

## 案2: Camera Vitals — カメラで心拍・呼吸・顔色を非接触計測

- **コンセプト**: タブレットのカメラに顔を30秒映すだけで、**rPPG（顔の微細な色変化から脈拍を推定する技術）**で心拍数を推定し、表情から気分・疲労の傾向を記録する。器具を取り出す手間を減らし、毎日の測定を習慣化する。
- **主な機能**
  - カメラでの心拍推定（rPPG）、呼吸数推定
  - 顔のむくみ（宇宙では体液が頭部へ移動する“ムーンフェイス”）の日次比較
  - 表情・音声日記からの気分スコア（自己申告と併用）
  - 推定値と実測値（血圧計等）を併記し、精度の限界も表示
- **使用データ**: HRP の体液シフト・行動健康に関する資料、オープンなrPPGアルゴリズム（POS法など）
- **技術スタック例**: MediaPipe Face Mesh、TensorFlow.js、WebRTC（ブラウザ内で処理しデータを外に出さない）
- **差別化ポイント**: 課題文の「カメラ画像による入力」を最も先進的に実現。デモで会場の人を実際に測れるインパクト
- **MVP範囲（2日）**: 心拍推定 + 顔写真の日次比較 + 気分記録
- **リスク・注意点**: 照明や動きで精度が落ちる。推定値であることを明示し、医療機器ではないと明記

## 案3: Crew Wellness Quest — ゲーミフィケーションで健康習慣を続けるアプリ

- **コンセプト**: 測定・運動・睡眠・食事を「デイリークエスト」化。達成すると基地の“士気メーター”が上がり、クルー全員の協力ゴールも用意。孤立・閉鎖環境での**行動健康（メンタル）**にも効く設計。
- **主な機能**
  - デイリークエスト（例: 朝の血圧測定、2時間の運動、8時間睡眠、水分補給）
  - 連続達成ストリーク、バッジ
  - クルー協力ミッション（全員が今週の運動目標達成で「地球の家族からのビデオ」解放など）
  - 気分ログ（絵文字5段階）と睡眠の相関グラフ
  - 「今日は休むべき」判定（無理に続けさせない設計）
- **使用データ**: ISS の運動プロトコル（1日約2時間の運動）に関する公開情報、HRPの行動健康リスク資料
- **技術スタック例**: React / Flutter、ローカルDB
- **差別化ポイント**: 課題文で提案されているゲーミフィケーションを中心に据え、「続けられる仕組み」を重視
- **MVP範囲（2日）**: クエスト8種、ストリーク、気分×睡眠グラフ
- **リスク・注意点**: ゲーム要素だけで健康評価が浅いと見られないよう、指標の評価画面を必ず持つ

## 案4: Flight Surgeon Bridge — 通信遅延を前提とした「地上医師への相談パッケージ」生成

- **コンセプト**: 火星ミッションでは地上との往復に最大40分以上かかる。異常が出たとき、**医師が一度で判断できる情報**（症状・指標の推移・実施済みの処置）を自動でまとめて送る。返事を待つ間にクルーができる応急対応も案内。
- **主な機能**
  - 症状入力ウィザード → 必要な追加測定を提案
  - 指標の推移とアラート履歴をまとめた「相談パッケージ」の自動生成（データ量を最小化）
  - 通信遅延・帯域を表示し、送信待ちキューを管理
  - 返事を待つ間の対応フローチャート（例: 発熱時のチェックリスト）
  - SI による要約（相談文の下書き）
- **使用データ**: HRP資料、宇宙医学の公開文献、JPL Horizons（遅延時間の算出）
- **技術スタック例**: React、LLM API（要約・下書き）、PDF生成
- **差別化ポイント**: 「地球からの距離」というハザードに正面から向き合い、**いつ地上に頼るべきか**という課題文の問いに具体的な答えを出す
- **MVP範囲（2日）**: 症状3パターン、パッケージ生成、遅延シミュレーション
- **リスク・注意点**: SIの要約に誤りが混ざらないよう、元データを必ず添付する構成にする

## 案5: Habitat Health Twin — 環境（放射線・CO₂・重力）と体調をつなげる「デジタルツイン」

- **コンセプト**: 宇宙船・ISS・ローバー・月/火星基地など**環境を切り替え可能**にし、その環境の放射線量・CO₂濃度・重力レベルと、本人の指標を同時に表示。「CO₂が高い日は頭痛が増えている」など、環境と体調の関係に気づかせる。
- **主な機能**
  - 環境選択（ISS / 月面基地 / 火星基地 / 与圧ローバー）
  - 環境データパネル（放射線の累積被ばく、CO₂、重力レベル）
  - 本人の指標と環境データの重ね合わせグラフ、相関の自動検出
  - 累積被ばく量と生涯被ばく制限の目安を可視化
  - 環境別の注意点（例: 低重力 → 骨・筋肉、閉鎖環境 → CO₂）
- **使用データ**: Curiosity RAD（火星の放射線）、ISS 環境データの公開情報、DONKI（宇宙天気）、HRPの資料
- **技術スタック例**: React + D3.js、Python（相関分析）
- **差別化ポイント**: 課題文の「様々な環境での健康インサイト」に対応し、5つのハザードを“環境データ”として可視化
- **MVP範囲（2日）**: 環境3種、指標4種、ダミー60日分データ
- **リスク・注意点**: 相関＝因果ではないことを明示
