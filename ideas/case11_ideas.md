# Case 11: Lunar Landing Site Navigator — アプリ提案

> **テーマ要約**: 月の南極への着陸ミッションは、太陽の位置（発電・熱）と地球の位置（直接通信）の制約が非常に厳しい。着陸地と日付を素早く比較し、地平線に対する太陽と地球の位置を可視化して**発電の見込みと地球との通信可能時間**を評価できる、直感的なツールをつくる。
> **背景**: 既存ツール（Quickmap、Moon Trek、JPL Horizons）は専門的で、複数シナリオの素早い比較には向かない。打ち上げ延期などで着陸日・着陸地を変える必要が出たとき、すぐ代替案を評価できることが重要。
> **技術のポイント**: ①天体暦（Sun / Earth の位置）は JPL Horizons や SPICE で計算 ②地平線は LOLA の地形データから計算（月には大気がないので屈折なし） ③太陽高度角が発電の鍵 ④南極では地球が地平線付近にあり、秤動（libration）で見え隠れする
> ※ case12.txt は本ファイルと同じ課題文のため、[case12_ideas.md](case12_ideas.md) では**別の切り口の5案**を提案しています。

---

## 案1: Site & Date Compare Board — 「着陸地 × 日付」を並べて比べる比較ボード

- **コンセプト**: 最大4つの「着陸地 × 着陸日」の組み合わせを横に並べ、それぞれの**日照率・太陽高度・地球が見える時間・次の日没 / 地球の沈むまでの時間**をカードとグラフで比較する。課題の中心である「素早いシナリオ比較」を最優先に設計。
- **主な機能**
  - 着陸地リスト: Apollo 各着陸地、Artemis III 候補地域（Nobile Rim、Malapert Massif、Haworth、Mons Mouton など）、CLPS の着陸地、他国の着陸地（Chandrayaan-3、SLIM、嫦娥など）+ 任意座標の入力
  - 各シナリオの指標: 着陸後14日間の日照率、平均太陽高度、地球可視率、最初の日没 / 地球の沈むまでの残り時間
  - 時間軸グラフ: 太陽高度と地球高度（地形の地平線を考慮）を重ねたグラフ、日照・通信可能時間を帯で表示
  - 「合格 / 要注意 / 不可」の判定（しきい値はユーザーが設定）
  - 比較結果の共有URL・CSV出力
- **使用データ**: LOLA 南極 DEM（高解像度）、JPL Horizons API / NAIF SPICE カーネル（DE440、月の姿勢）
- **技術スタック例**: Python（SpiceyPy で天体位置計算、numpy で地平線マスク計算）、FastAPI、React + Plotly
- **差別化ポイント**: 「延期で着陸日が2週間ずれたらどうなる？」に数クリックで答えられる
- **MVP範囲（2日）**: 南極の候補地8か所の地平線マスクを事前計算し、日付は自由に選べるようにする
- **リスク・注意点**: 地平線マスク（全方位の地形の見かけの高さ）の計算は重い。事前計算して保存しておく

## 案2: Horizon Panorama View — 着陸地点に立った視点で「太陽と地球がどこに見えるか」

- **コンセプト**: 着陸地点に立った360度のパノラマ（LOLA 地形から生成した地平線の輪郭）の上に、太陽と地球の通り道を描く。**「太陽が山の陰に隠れる」「地球が地平線すれすれ」**という南極特有の状況が直感的にわかる。
- **主な機能**
  - 360度パノラマの地平線シルエット（方位角 × 高度）
  - 太陽・地球の軌跡（1か月分）を描画、地形で隠れる区間を色分け
  - 時間スライダーで太陽・地球を動かす
  - 地平線を「月の球面の縁だけ」とした場合と「実際の地形」の場合の比較（地形の影響を見せる）
- **使用データ**: LOLA DEM、SPICE / Horizons
- **技術スタック例**: D3.js（パノラマ図）、Python（地平線計算）
- **差別化ポイント**: 専門家にも一般にもわかる最も直感的な表現。教育用途にも強い
- **MVP範囲（2日）**: 候補地4か所のパノラマ + 時間スライダー
- **リスク・注意点**: 遠くの山まで含めて地平線を計算するには広い範囲の DEM が必要（数十〜100km 以上）

## 案3: Power & Comm Calculator — 発電量と通信可能時間を「ミッション成立性」に変換

- **コンセプト**: 太陽高度や日照時間を見せるだけでなく、ユーザーが入力した**太陽電池の向き・面積、バッテリー容量、消費電力**から、着陸後の電力収支とバッテリー残量の推移をシミュレーション。地球が見える時間からデータ送信可能量も計算し、「このミッションは何日生き残れるか」を出す。
- **主な機能**
  - 着陸機の設定（垂直パネル / 水平パネル、面積、効率、バッテリー、消費電力）
  - 電力収支グラフとバッテリー残量（ゼロになる日時を警告）
  - 地球可視時間 × 通信速度 = 送信可能データ量
  - 「バッテリーが持つ最も遅い着陸日」の逆算
- **使用データ**: LOLA DEM、SPICE / Horizons、太陽定数
- **技術スタック例**: Python 計算エンジン + React UI
- **差別化ポイント**: 南極では太陽が低いので**垂直パネル**が有利、など工学的な示唆まで出せる
- **MVP範囲（2日）**: パネル2種 × バッテリー計算 × 候補地4か所
- **リスク・注意点**: 熱（夜間のヒーター電力）は簡略化することを明記

## 案4: Lunar Day Animator — 月の1日（約29.5地球日）を3Dで早送り

- **コンセプト**: 南極地域の3D地形の上で、太陽光と影の動きを早送りアニメーションで見せる。クレーターの永久影、ずっと日が当たる「峰（ピーク）」、地球の見え隠れがひと目でわかる。日付を変えると季節（月の自転軸の傾きはわずか約1.5度）による違いも見える。
- **主な機能**
  - LOLA 地形の3D表示 + 太陽光源のリアルタイム影計算
  - 地球の方向を示す矢印と、地球が見える地点のハイライト
  - 指定地点のマーカーと、その地点の日照 / 通信状況の時刻表
  - 永久影領域（水の氷がある可能性）の表示
- **使用データ**: LOLA DEM、LRO の照明マップ（LOLA 由来の平均日照率マップ）、SPICE
- **技術スタック例**: CesiumJS または Three.js（シャドウマップ）、事前計算した太陽ベクトル
- **差別化ポイント**: 課題文の「地球と月の極端な違いを見せる」を視覚的に最も強く表現できる
- **MVP範囲（2日）**: 南極周辺 50km 四方の3D表示 + 1か月アニメーション
- **リスク・注意点**: GPU の影計算は近似。正確な数値は案1の計算エンジンを使う

## 案5: Moon Mission Planner Game — 着陸地と日付を選んで探査機を生き延びさせる教育ゲーム

- **コンセプト**: 生徒や一般の人向けに、「この探査機を何日間生き延びさせられるか？」を競うゲーム。着陸地・日付・パネルの向きを選ぶと、太陽と地球の動きに従ってシミュレーションが進む。南極ミッションがなぜ難しいかを遊びながら学べる。
- **主な機能**
  - ミッションカード（「水の氷を探せ」「地球に写真を送れ」など）
  - 選択 → シミュレーション → 結果（運用日数、送信できたデータ量）
  - 「なぜ失敗したか」の振り返り（日没で電力切れ、地球が隠れて通信不能など）
  - リーダーボード
- **使用データ**: 案1・3と同じ計算結果を利用
- **技術スタック例**: Phaser.js / React、事前計算データ
- **差別化ポイント**: 課題が挙げる「教育者・一般の人」への対象拡大に応える
- **MVP範囲（2日）**: 着陸地4か所、ミッション3種
- **リスク・注意点**: 単体だと「素早い比較ツール」という主目的から外れるので、案1の教育モードとして組み込む
