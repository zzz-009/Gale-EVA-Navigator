## 案1: Slip Impact Analyzer — 「延期したらどうなる？」を一瞬で示すスケジュール影響分析

- **コンセプト**: 課題文の「打ち上げ延期やハードウェアの遅れで日付・場所を見直す」場面に特化。基準の着陸日を決めると、**前後90日間の毎日の着陸について**日照率・通信可能時間を計算し、カレンダー上で「良い日 / 悪い日」を色分けする。
- **主な機能**
  - カレンダーヒートマップ（着陸日ごとのミッション成立性スコア）
  - 「延期できる最大日数」「次の良い着陸ウィンドウ」の自動検出
  - 同じ地域の代替着陸地を自動提案（近くで条件が良い地点）
  - 基準案と代替案の差分表示（「日照 −12%、通信 +8%」）
- **使用データ**: LOLA 南極 DEM、SPICE / JPL Horizons
- **技術スタック例**: Python（SpiceyPy、numpy でベクトル化して高速計算）、React + カレンダーヒートマップ
- **差別化ポイント**: 課題の背景文で強調されている「固定スケジュールでは進まない現実」に直接応える
- **MVP範囲（2日）**: 候補地5か所 × 180日分のスコアを事前計算
- **リスク・注意点**: スコアの重み（日照と通信のどちらを重視するか）をユーザーが調整できるようにする

## 案2: Suitability Heatmap — 南極域の「どこに降りるといいか」を日付別に地図で塗る

- **コンセプト**: 点（着陸地リスト）ではなく、**南極域の全グリッドについて**日照率・地球可視率を計算し、着陸日ごとの適性マップを作る。地図をクリックした地点がそのまま候補になるので、リストにない新しい着陸地を探せる。
- **主な機能**
  - 日照率マップ、地球可視率マップ、両方を満たす領域のマップ
  - 傾斜マップを重ねて「着陸に安全な平らな場所」との積集合を表示
  - 日付スライダーで適性領域が変化する様子をアニメーション
  - 地図クリック → 案1の詳細分析へ
- **使用データ**: LOLA DEM（傾斜・地平線）、LRO の照明関連プロダクト、SPICE
- **技術スタック例**: Python（GPU / numba で地平線計算を並列化）、COG タイル、MapLibre（極座標投影）
- **差別化ポイント**: 「任意座標の入力」を地図上で直感的にでき、場所選びの探索ツールになる
- **MVP範囲（2日）**: 50km四方 × 粗いグリッド（例: 200m）× 数日分
- **リスク・注意点**: 計算量が大きいので、解像度と範囲を絞る。地平線マスクを事前計算するのが鍵

## 案3: Science vs Engineering Negotiation Board — 科学チームと工学チームの調整ツール

- **コンセプト**: 課題文の「科学チームと工学チームの調整」を支援。科学チームは「永久影クレーターに近いほど良い（氷がある）」、工学チームは「日照と通信が長いほど良い」。両者の評価軸を並べ、**どこが両立点か（パレート最適）**を可視化する。
- **主な機能**
  - 科学スコア（永久影までの距離、氷の存在可能性）と工学スコア（日照・通信・傾斜）の2軸散布図
  - パレートフロント（どちらかを下げないともう一方を上げられない境界）の表示
  - 各チームが重みを入力し、合意案をリアルタイムで探る共同編集モード
  - 決定理由を記録する「判断ログ」
- **使用データ**: LOLA、Diviner（表面温度・永久影の温度）、LEND / LAMP など氷に関する公開データ、SPICE
- **技術スタック例**: React + Plotly、Firebase（共同編集）、Python 計算
- **差別化ポイント**: 技術的な可視化に加え、**意思決定のプロセス**そのものを支援する
- **MVP範囲（2日）**: 候補地10か所、2軸の散布図と重みスライダー
- **リスク・注意点**: 科学スコアの根拠データが限られるので、簡略化した指標であることを明示

## 案4: Lunar Sky API & Widget — どこにでも埋め込める「月面の空」計算API

- **コンセプト**: 計算エンジンを**Web API + 埋め込みウィジェット**として公開。座標と日時を渡すと、太陽・地球の方位・高度、地形を考慮した可視性、次の日没 / 地球の沈む時刻を返す。教育サイトやミッションチームの社内ツールに組み込める。
- **主な機能**
  - REST API: `/sky?lat=-89.5&lon=-137&time=2027-01-01T00:00Z`
  - 埋め込み用ウィジェット（iframe で「この地点の今の空」を表示）
  - URLパラメータで状態を共有
  - API ドキュメント（OpenAPI）とサンプルコード
- **使用データ**: LOLA DEM（地平線マスク）、SPICE
- **技術スタック例**: FastAPI、Redis キャッシュ、Web Components
- **差別化ポイント**: 1つのアプリで終わらず、**他のツールの部品になる**基盤として価値を出す
- **MVP範囲（2日）**: API 2本（空の状態、時間範囲の可視性）+ ウィジェット1つ
- **リスク・注意点**: 地平線マスクを事前計算した地点でのみ地形を考慮し、それ以外は「地形なし」と明示

## 案5: Moon Window AR — スマホを空にかざして「月の南極から見た空」を体験

- **コンセプト**: スマホの方位センサーを使い、**月の南極の着陸地点に立っているかのように**周囲を見回せるARアプリ。地平線の山々、地平線すれすれを回る太陽、ときどき隠れる地球が見える。科学館・授業で「なぜ南極ミッションは難しいか」を体感させる。
- **主な機能**
  - スマホの向きに合わせて月面の地平線パノラマを表示
  - 太陽・地球の現在位置（実際の現在時刻での計算 or 任意の日時）
  - 「地球が見えないと通信できない」「太陽が低いと発電できない」の解説ポップアップ
  - 地点の切り替え（南極 vs Apollo 11 の着陸地 — 地球の見え方の違いがわかる）
- **使用データ**: LOLA DEM、SPICE / Horizons
- **技術スタック例**: WebXR / DeviceOrientation API、Three.js、事前計算パノラマ
- **差別化ポイント**: 教育・一般向けの体験として最もインパクトが大きい
- **MVP範囲（2日）**: 地点3か所のAR表示
- **リスク・注意点**: iOS ではセンサー利用の許可が必要。デスクトップ用のマウス操作版も用意する
