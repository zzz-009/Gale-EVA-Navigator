# Case 3: Junior Astronaut Mission Trainer — アプリ提案

> **テーマ要約**: 7〜12歳の子どもが月・火星の前哨基地を運営し、生命維持・放射線遮蔽・電力・食料生産・通信遅延などの**トレードオフ**を体験するゲーム/アプリをつくる。
> **重要ポイント**: ①コストのない「安全な選択肢」を作らない ②管理する資源は2〜3個に絞る ③NASA実データ（DONKI, OSDR, 火星表面データ）を使い、出典を明示 ④ブラウザで登録不要 ⑤リプレイ性

---

## 案1: Moon Base Day-by-Day — 太陽フレア実データで動く月面基地サバイバル

- **コンセプト**: 1ターン = 1日。プレイヤーは**電力・酸素・シールド**の3資源を配分する。イベントとして、DONKI に記録された**実際の太陽フレア・CME・高エネルギー粒子（SEP）イベント**が発生し、「シールドに電力を回すか、研究を続けるか」の決断を迫られる。
- **主な機能**
  - 3つの資源メーター（電力 / 酸素 / シールド）と、配分スライダー
  - DONKI の過去イベントをランダムに選んでシナリオ化（毎回違う展開 → リプレイ性）
  - イベント後に「これは◯年◯月◯日に本当に起きた太陽フレアです」と出典カード表示
  - 「今日の本物の宇宙天気」モード（DONKI のライブデータで当日の難易度が変わる）
  - ミッション終了時に「あなたの判断」と「実際のNASAの考え方」を比較する振り返り画面
- **使用データ**: NASA DONKI API（FLR, CME, SEP, GST）、月面の昼夜サイクル（約14日ずつ）
- **技術スタック例**: Phaser.js または React + Canvas、DONKI API（api.nasa.gov）
- **差別化ポイント**: 課題文の「放射線遮蔽の判断を実際の宇宙天気データに結びつける」という“Stand Out”条件をそのまま満たす
- **MVP範囲（2日）**: 3資源、10日間ミッション、DONKIイベント20件を埋め込み + ライブモード
- **リスク・注意点**: ライブデータとアーカイブデータの区別を明示（課題文で「静的データをライブと偽らない」と明記されている）

---

## 案2: Mars Message Delay — 通信遅延を体験する「管制室 vs 火星クルー」2人協力ゲーム

- **コンセプト**: 2人1組（または親子・クラス）で、片方が地球の管制室、もう片方が火星基地のクルー。**メッセージは実際の地球-火星距離に応じた遅延（片道 約4〜24分 → ゲーム内で縮尺）**で届く。緊急時にクルーが自分で判断しないといけない状況を体験する。
- **主な機能**
  - 2画面（管制室ビュー / 基地ビュー）、同一端末の分割モードもあり
  - 当日の地球-火星距離から遅延時間を計算して表示
  - 管制室は「データは多いが遅い」、クルーは「情報は少ないが即断できる」非対称設計
  - 月ミッション（遅延 約1.3秒）との比較モード
- **使用データ**: JPL Horizons（地球-火星距離）、Curiosity REMS の気象データ、DONKI
- **技術スタック例**: WebSocket（Socket.io）またはFirebase、React
- **差別化ポイント**: 課題文に挙がっている「通信遅延」をメイン体験に据えたユニークな設計。協力プレイで教室・家庭で盛り上がる
- **MVP範囲（2日）**: 同一端末2分割モード、シナリオ3本
- **リスク・注意点**: 遅延を実時間でやると子どもが飽きるので「1分 = 6秒」などの縮尺を明示

## 案3: Space Greenhouse Keeper — 火星の温室で食料を育てる資源ゲーム

- **コンセプト**: 火星基地の温室で野菜を育てる。光（電力）・水・温度のバランスを取りながら、クルーの食料を確保する。植物実験の実データ（宇宙での植物栽培研究）を根拠にした「育ちやすさ」パラメータを使う。
- **主な機能**
  - 作物カード（レタス、ジャガイモ、トマト等）ごとに必要な電力・水・日数
  - 火星の1日（sol = 約24時間40分）や季節、砂嵐で太陽光発電が減るイベント
  - 「電力を温室に回すと、夜のヒーターが足りない」などのジレンマ
  - 作物ごとに ISS での栽培実験（Veggie など）の豆知識カード
- **使用データ**: NASA OSDR（植物の宇宙実験データ）、Curiosity REMS（火星の気温・日照）、Veggie 実験情報
- **技術スタック例**: Phaser.js、JSONで作物パラメータ管理
- **差別化ポイント**: 「食料生産」という課題要素を深掘り。育成ゲームは7〜12歳に親しみやすく、自然とトレードオフを学べる
- **MVP範囲（2日）**: 作物4種、30 sol のミッション、砂嵐イベント
- **リスク・注意点**: 作物パラメータの根拠が曖昧になりがち。出典を示せない数値は「ゲーム用に簡略化」と明記

## 案4: Mission Control Kids Dashboard — 本物っぽい管制ダッシュボードで基地を見守る

- **コンセプト**: NASAの管制室風ダッシュボードで、基地の状態をモニタリング。警告ランプが点灯したら、選択肢から対応を選ぶ。**大人の“本物感”に憧れる子ども心**をくすぐるデザイン。
- **主な機能**
  - メーター・グラフ・警告ランプで構成された管制画面（ただし表示は3資源に限定）
  - 「宇宙飛行士の健康」パネル: 被ばく量の累積（OSDR / Curiosity RAD の実測値を基準に）
  - 用語はホバーでやさしく解説（例: 「放射線量（ミリシーベルト）ってなに？」）
  - クラス全員で同じミッションをプレイし、結果を比較する教室モード
- **使用データ**: DONKI、Curiosity RAD（火星表面の放射線量）、OSDR
- **技術スタック例**: React + Recharts、DONKI API
- **差別化ポイント**: 課題文で例示された「ダッシュボード型ミッションコントロール」を子ども向けに最適化
- **MVP範囲（2日）**: ダッシュボード1画面 + イベント15種
- **リスク・注意点**: 情報量が多すぎると7歳には難しいので、年齢で表示量を切り替えるモードを用意

## 案5: Choose Your Mission — 分岐ストーリーで学ぶ「火星への180日」

- **コンセプト**: 絵本のような分岐ストーリー。プレイヤーは小さな宇宙飛行士となり、出発から火星基地での生活までの重要な判断をしていく。**どの選択肢にも必ずコストがある**設計で、失敗しても「なぜダメだったか」がわかるやさしいエンディング。
- **主な機能**
  - イラスト付きのシーン + 2〜3択の選択
  - 選択ごとに資源メーターが変化（2〜3資源）
  - 複数のエンディング（成功・部分成功・帰還）とエンディング図鑑（リプレイ動機）
  - 読み上げ機能（低学年・読字が苦手な子ども向け）
- **使用データ**: DONKI（出発時期の宇宙天気）、OSDR（長期滞在の健康影響の知見）、NASAの火星画像
- **技術スタック例**: Ink（分岐スクリプト）+ Web、Web Speech API
- **差別化ポイント**: 7歳でも遊べる最も低いハードル。失敗を“罰”にしない設計（課題文の配慮点に対応）
- **MVP範囲（2日）**: 分岐ポイント8つ、エンディング4種
- **リスク・注意点**: 物語中心になると「実データ」要素が薄くなるので、各シーンに実データカードを最低1つ入れる
