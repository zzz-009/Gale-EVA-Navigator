# Case 2: Earth System Trend Detective — アプリ提案

> **テーマ要約**: 地球観測ミッション（MODIS, OMI, AIRS, GPM）やモデル（MERRA-2, GLDAS）の変数を選び、時系列を可視化し、「何が・どこで・どれだけ変化し・それが統計的に有意か」を判定するツールをつくる。
> **必須要素**: ①変数選択 ②地域ごとのデータ取得 ③時系列の可視化 ④変化率の算出 + 有意性検定（t検定 / Mann-Kendall / 信頼区間）
> **想定ユーザー**: 高校生・大学生・科学的素養のある一般市民 → 「データ探偵」になってもらう

---

## 案1: Data Detective Wizard — 質問に答えるだけで「事件（トレンド）」を捜査

- **コンセプト**: 「どこを調べたい？」「何が気になる？（暑さ、雨、大気汚染、植生…）」といった3〜4問の質問に答えると、適切な変数と地域が自動で選ばれ、時系列グラフと有意性判定の「捜査報告書」が出る。
- **主な機能**
  - 質問ウィザード → 変数候補の提示（各変数に“やさしい定義”付き）
  - 地図で地点/矩形を選択 → データ取得
  - 時系列グラフ + 線形回帰直線 + 95%信頼区間
  - Mann-Kendall 検定と Sen's slope による「有意 / 有意でない」の判定と、平易な言葉での解説
  - 「データ期間を延ばしたら有意になるか？」スライダー
  - デモ事件ファイル（例: アラル海周辺の地表面温度、大都市上空のNO₂、アマゾンの植生指数）
- **使用データ**: NASA GES DISC Giovanni（時系列取得）、MERRA-2、GLDAS、MODIS（AppEEARS経由）、OMI NO₂
- **技術スタック例**: Python（FastAPI + pymannkendall + statsmodels）、React + Plotly、Leaflet
- **差別化ポイント**: 課題文の「短い質問に答えて変数を探す」「デモ例を見られる」という推奨アプローチをそのまま製品化
- **MVP範囲（2日）**: 変数10種程度に絞り、月次データのみ対応。デモ事件3件
- **リスク・注意点**: リアルタイム取得が重い場合は、事前にキャッシュした地域データで動かす

---

## 案2: Trend Heatmap Explorer — ピクセルごとの「有意なトレンド地図」

- **コンセプト**: 1地点ではなく**地域全体の各グリッドで**トレンドと有意性を計算し、「どこで増えて、どこで減っているか」を地図で一望する。課題の核心である「同じプロセスが地域によって逆向きのトレンドを生む」ことを視覚的に示せる。
- **主な機能**
  - 変数・期間・地域を選ぶとトレンド（傾き）マップを描画（赤=増加、青=減少）
  - 有意でないピクセルはハッチング（斜線）で表示
  - ピクセルクリック → その地点の時系列と検定結果をポップアップ
  - 2地域比較モード（例: 同じ温暖化でも降水が増える地域と減る地域）
- **使用データ**: MERRA-2（気温・降水）、GLDAS（土壌水分・蒸発散）、GPM IMERG（降水）
- **技術スタック例**: Python（xarray + dask）で事前計算 → COG/タイル化、MapLibre GL JS
- **差別化ポイント**: 「どこで変わっているか」に最も直接的に答える。研究者的な見た目で説得力が高い
- **MVP範囲（2日）**: 日本周辺 or 1大陸 × 変数3種を事前計算して配信
- **リスク・注意点**: 多重検定問題（多数のピクセルで偶然有意になる）があるので、FDR補正のオプションや注意書きを入れると科学的に誠実

---

## 案3: Season Remover — 季節変動を「はがして」本当のトレンドを見つける教材ツール

- **コンセプト**: 気温や植生は季節サイクルが大きく、そのままではトレンドが隠れる。ユーザーが**「生データ → 季節成分 → 残差 → トレンド」**と段階的に分解していく過程を、アニメーションで体験しながら学ぶ。
- **主な機能**
  - STL分解（トレンド・季節・残差）のステップ表示
  - 「季節を除去する前 / 後」で検定結果がどう変わるかを比較
  - Seasonal Mann-Kendall 検定にも対応
  - 用語解説（自己相関、p値、信頼区間）をクリックで表示
- **使用データ**: MODIS NDVI、MERRA-2 地上気温、AIRS
- **技術スタック例**: Python（statsmodels STL）、Observable / Plotly のアニメーション
- **差別化ポイント**: 課題文の「季節サイクルを除かないと見えないトレンドがある」という一文を中心に据えた教育性の高い設計
- **MVP範囲（2日）**: プリセット地点5か所 + 自由入力1か所
- **リスク・注意点**: 統計手法の説明が難しくなりすぎないよう、高校生レベルの言葉で書く

## 案4: News-to-Data Detective — ニュース記事からSIが調べるべき変数を提案

- **コンセプト**: 「◯◯湖が干上がっている」「△△市で猛暑」といったニュース記事のURLや文章を貼ると、SI（AI）が関連する地域・変数・期間を推定し、実データで「本当にトレンドがあるか」を検証する。**ニュースの主張をデータでファクトチェック**する体験。
- **主な機能**
  - 記事テキスト → 地名抽出（ジオコーディング） + 変数候補（LLM）
  - 候補変数ごとの時系列と有意性判定を一覧表示
  - 「記事の主張とデータは一致？」の判定と根拠説明
  - 地域の特徴（砂漠、熱帯雨林、河口、大都市上空）からの変数推薦
- **使用データ**: Giovanni / MERRA-2 / GLDAS / OMI、ジオコーディング（OpenStreetMap Nominatim）
- **技術スタック例**: LLM API（変数カタログを渡して選ばせる構成）、FastAPI、React
- **差別化ポイント**: 課題文で触れられているSI活用（ニュース・論文・地域特性から候補を探す）を実装。メディアリテラシー教育にもなる
- **MVP範囲（2日）**: 変数カタログ20種、デモ記事3本
- **リスク・注意点**: SIが変数を「選ぶ」だけにして、統計計算は決定的なコードで行う（数値をSIに作らせない）

## 案5: Trend Detective Classroom — 先生が「事件」を出題し、生徒が捜査するクラス対戦

- **コンセプト**: 先生が地域と期間を設定して「事件」を出題。生徒チームは変数を選び、トレンドと有意性を見つけて「捜査報告書」を提出。正しく有意なトレンドを見つけるとポイント、有意でないのに「変化あり」と主張すると減点。
- **主な機能**
  - 出題モード / 捜査モード / 発表モード
  - 報告書テンプレート（何が・どこで・どれだけ・有意か・原因の仮説）
  - チームのスコアボード
  - 「有意でなくても面白い発見」賞（課題文の“有意でなくても興味深い”に対応）
- **使用データ**: 案1と同様（Giovanni、MERRA-2、GLDAS など）
- **技術スタック例**: Firebase（リアルタイム同期）、React、Python統計API
- **差別化ポイント**: 「データ探偵」コンセプトを授業で使える形にし、継続利用・普及のストーリーが描ける
- **MVP範囲（2日）**: 事件3件、1クラス分の同期
- **リスク・注意点**: 教育機能に寄りすぎると必須要件（可視化+統計）が薄く見えるので、分析部分は案1レベルを確保する
