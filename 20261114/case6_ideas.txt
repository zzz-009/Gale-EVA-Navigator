# Case 6: Adapting Farms with NASA Data — アプリ提案

> **テーマ要約**: NASAの地球観測データ + 地域の土壌情報 + 作物特性 + 農家の優先事項を組み合わせ、土壌の健康を高め、気候変化に強い**輪作（クロップローテーション）戦略**を検討できる意思決定支援ツールをつくる。
> **使えるデータ例**: SMAP（土壌水分）、ECOSTRESS（地表面温度・蒸発散）、GPM（降水）、Landsat / MODIS（植生指数）、NASA POWER（気象）、GRACE / GRACE-FO（地下水・水貯留）、SRTM（標高）
> **要件のポイント**: 既存の輪作を含む**3つ以上の戦略を比較**／推奨理由・根拠・メリット・情報の欠落・要確認リスクを説明／農家の判断を「置き換えない」支援ツールであることを明示

---

## 案1: Rotation Compare Board — 3つの輪作案を「根拠つき」で並べて比べる

- **コンセプト**: 畑の位置と現在の輪作、優先事項（節水 / 収入 / 土づくり）を入力すると、**現行案 + 代替案2つ以上**をカードで並べて比較。各カードに「なぜ提案したか」「根拠データ」「メリット」「データが足りない点」「地域の専門家に確認すべきリスク」を表示する。
- **主な機能**
  - 地図で圃場を選択 → NASA POWER / SMAP / GPM から過去20年以上の気候・水分条件を自動取得
  - 優先事項スライダー（節水、窒素固定、侵食防止、有機物増加、市場性、飼料価値）
  - 輪作案ごとのレーダーチャート比較
  - 根拠データへのリンク付き説明文
  - 「信頼度」表示と「ここは農家・普及指導員の判断が必要」マーク
- **使用データ**: NASA POWER API、SMAP L3/L4、GPM IMERG、SoilGrids（ISRIC）または農研機構の日本土壌インベントリ、作物特性DB（FAO ECOCROP 等）
- **技術スタック例**: Python（FastAPI）、React + Recharts、LLM API（説明文生成。数値はルールベースで計算）
- **差別化ポイント**: 課題文が求める「理由・根拠・メリット・欠落・リスク」の5項目を**フォーマットとして固定**し、説明責任を徹底
- **MVP範囲（2日）**: 対象地域1つ、作物15種程度、輪作案3つの比較
- **リスク・注意点**: 作物の推奨ロジックは透明なルールに。SIは説明の言い換えに限定すると信頼性が上がる

---

## 案2: Bare Field Finder — 「畑が裸になっている期間」を衛星で見つけてカバークロップを提案

- **コンセプト**: Landsat / MODIS の植生指数（NDVI）の時系列から、**畑に作物がない期間（裸地期間）**を自動検出。その期間の気温・降水・霜リスクに合うカバークロップ（緑肥）を提案し、侵食防止・有機物増加の効果を見積もる。
- **主な機能**
  - 圃場のNDVI時系列グラフと「裸地期間」の自動ハイライト
  - その期間の降水強度（GPM）と侵食リスクの重ね合わせ
  - カバークロップ候補（ヘアリーベッチ、エンバク、クリムソンクローバー等）の適合度表示
  - 霜の初日・終日の統計（NASA POWER の最低気温から算出）
- **使用データ**: Landsat / MODIS NDVI（AppEEARS で取得）、GPM IMERG、NASA POWER、SRTM（傾斜 → 侵食リスク）
- **技術スタック例**: Google Earth Engine / AppEEARS、Python、Leaflet
- **差別化ポイント**: 課題文の「畑が裸になる時期を示す」というアイデアを具体化。衛星データの価値がわかりやすい
- **MVP範囲（2日）**: 圃場3か所の事例、カバークロップ8種
- **リスク・注意点**: 圃場が小さい日本では MODIS（250m〜）は粗いので、Landsat（30m）や Sentinel-2 を使う

---

## 案3: Field Risk Map — 圃場内の「弱いところ」を地図で見える化

- **コンセプト**: 圃場や地域を格子に分け、**侵食リスク・水ストレス・霜が降りやすい場所**をヒートマップで表示。「この区画は乾きやすいので深根性の作物を」「この窪地は霜が溜まりやすい」といった区画ごとの提案につなげる。
- **主な機能**
  - レイヤー切替: 侵食リスク（SRTM傾斜 + 降水強度）、水ストレス（ECOSTRESS 蒸発散ストレス指標）、霜リスク（標高・窪地）、土壌水分（SMAP）
  - タイムライン: 過去の熱波・干ばつ年を選んで比較
  - シナリオスライダー: 「降水−20%」「気温+2℃」で各リスクがどう変わるか
  - 区画クリック → その区画に向く作物タイプの提案
- **使用データ**: SRTM、ECOSTRESS、SMAP、GPM、GRACE-FO（地域の地下水トレンド）
- **技術スタック例**: Python（xarray, rioxarray）でグリッド統一（リサンプリング）、MapLibre
- **差別化ポイント**: 課題文の「解像度の異なるデータを共通グリッドに統合」「圃場レベルの脆弱性の可視化」「シナリオスライダー」をすべてカバー
- **MVP範囲（2日）**: 1地域、レイヤー4種、シナリオスライダー2種
- **リスク・注意点**: SMAP（約9〜36km）は圃場単位では粗い。解像度の違いと限界をUI上で明示する

## 案4: Farmer Chat Advisor — 会話で優先事項を聞き取り、データで答えるSIアシスタント

- **コンセプト**: 地理空間データに慣れていない農家向けに、**チャット（音声入力も可）**で「水が足りなくて困っている」「冬の収入がほしい」などの悩みを聞き取り、NASAデータで地域条件を調べたうえで輪作のアイデアを返す。答えには必ずグラフと根拠を添える。
- **主な機能**
  - 音声 / テキストでの相談（スマホ前提、大きな文字）
  - 優先事項・制約（水の利用可能量、機械、販売先）を会話から抽出してプロフィール化
  - 回答に「根拠グラフ」と「この点は地域の普及指導員に確認を」の注記
  - 用語集（蒸発散、土壌水分偏差、NDVI など）をやさしく解説
- **使用データ**: NASA POWER、SMAP、GPM、作物特性DB
- **技術スタック例**: LLM API（Tool Use でデータ取得関数を呼ぶ構成）、Web Speech API、Next.js
- **差別化ポイント**: 課題文の「技術的経験の少ない農家にもわかりやすく」「農家が自分の優先事項を入力できる」に、最も自然なUIで応える
- **MVP範囲（2日）**: 相談シナリオ3本 + データ取得ツール3種
- **リスク・注意点**: SIが根拠なく推奨しないよう、回答はデータ取得結果に基づくことをシステム側で強制する

---

## 案5: Generations Farm Timeline — 「親の代からの気候変化」を振り返り、次の10年の輪作を考える

- **コンセプト**: 課題の着想元である「何世代にもわたる農業経験」に寄り添い、**過去40年の気候データを家族の農業の歴史と重ねて**振り返るタイムライン。「あの不作の年は実はこういう天候だった」と納得し、次の10年の輪作を考える。
- **主な機能**
  - 年表: NASA POWER（1981年〜）の気温・降水・熱ストレス日数と、農家が入力した出来事（不作、作物変更）を並べる
  - 「霜の終日が◯日早まった」「猛暑日が◯日増えた」などのトレンド表示（有意性検定つき）
  - GRACE / GRACE-FO による地域の水貯留量の長期変化
  - 過去の傾向を延長した「次の10年」で、各輪作案のリスクを比較
- **使用データ**: NASA POWER（長期の日別データ）、GRACE / GRACE-FO、MODIS NDVI（2000年〜）
- **技術スタック例**: React + D3.js（タイムライン）、Python（Mann-Kendall 検定）
- **差別化ポイント**: 感情に訴えるストーリー性と、長期データの説得力を両立。プレゼンで共感を得やすい
- **MVP範囲（2日）**: 架空（または実在）の農家1軒の40年タイムライン + 輪作案3つの比較
- **リスク・注意点**: 将来予測は単純延長であることを明示（気候モデルの予測ではない）
