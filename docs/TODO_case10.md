## 0. ゴールと発表デモ（3分）

1. 「火星には GPS がなく、地球に聞いても答えが返るまで最大40分。通信が途切れる場所も多い」
2. **本物の HiRISE の地図**を Google マップのように動かし、等高線・傾斜・（地質または熱）を重ねて、目的地までのルートを決める
3. 歩き出すと、**足あとが等高線の上に記録**されていく（線の色 = 傾斜、誤差の円付き）
4. **通信遮断モード**に切り替える → それでも記録は続き、未送信の件数が増えていく
5. 「**迷った**」ボタン → 最後に確定した地点・いちばん近い足あと・目印・帰還の限界が出る → **とんぼ返り**の案内で基地へ戻る
6. 通信が戻ると、たまった記録が送信される

**最低ライン（P0）は手順 2〜5（M2、11/15 01:00）**。

## 5. データ契約（前処理 → フロントの受け渡し形式）

| ファイル | 中身 |
|---|---|
| `region.json` | 範囲（緯度経度）、地形データの名前・解像度・出典 URL、グリッドの大きさ、緯度経度への変換情報 |
| `hillshade.png` / `slope_class.png` | 陰影 / 傾斜の4段階（緯度経度の範囲は `region.json`）|
| `elev.f32` | 標高のグリッド（情報ウィンドウと足あとの標高に使う）。行優先・リトルエンディアン、値なしは NaN |
| `contours.geojson` | 等高線。属性 `elev_m`、`index`（太い線かどうか）。座標は緯度経度 |
| `hazard_zones.geojson` | **斜面リスクの危険エリア**（参考サイト風の丸い多角形）。属性 `kind`（steep / sand）、`level`（no_go / limited）、`max_slope_deg`、`mean_slope_deg`、`area_m2`、`label`、`source`。作り方は [ui_spec_map.md](ui_spec_map.md) 3.6 |
| `landmarks.json` | 目印（約10か所）: `id, name, lat, lon, kind`。**名前は公式の地名でない限り「目印A」などの仮の名前**にする |
| `base.json` | 基地の位置、アンテナの高さ（初期値 10 m）|
| `targets.json` | 科学目標（2〜3か所）と、選んだ理由 |
| `sim_track.json` | デモ用の足あと（基地 → 目標へ歩き、途中で予定ルートから外れて迷う場面を含む）。`t, lat, lon, src` |
| `viewshed.png`（P1）| 基地から電波が届く範囲 |

**足あとの記録の形式（IndexedDB）**
```ts
type TrackPoint = {
  id: string; t_utc: string; sol: number; lmst: string;
  lat: number; lon: number; elev_m: number | null; heading_deg: number;
  err_m: number;              // 誤差の円の半径
  src: 'dr' | 'fix';          // 推測航法 / 目印で確定
  note?: string;              // サンプル採取などのメモ
  sent: boolean;              // 基地・地球へ送信済みか
};
```

## 6. 計算仕様

### 6.1 等高線と傾斜
- 等高線の間隔: 地形データが 2 m 以下なら **5 m（25 m ごとに太い線）**、200 m の代用データなら 50 m（250 m ごとに太い線）
- 傾斜の4段階（UI で変更可）: 0〜5° 安全 / 5〜15° 注意 / 15〜20° 制限 / 20° 超 通行不可
- 画面に「この地形データより小さい岩などの障害物は表示されない」と明記する

### 6.2 推測航法と誤差の円（`deadReckoning.ts`）
- 誤差の半径 = 最後に確定したときの誤差 + **k × 確定してから進んだ距離**（k の初期値 0.03 = 3%。UI に式を表示する）
- 目印で確定したら、誤差を初期値（例: 5 m）に戻し、`src = 'fix'` で記録する

### 6.3 足あとの記録（`track.ts`）
- デモでは `sim_track.json` を早送りで再生し、1点ずつ記録する（「シミュレーション」と表示する）
- 表示: 足あとの線（区間の色 = 傾斜の4段階）、誤差の円（最新の点）、立ち寄りのメモの印
- 集計: 歩いた距離（地表に沿った距離）、累積の登り・下り、経過時間、実際の縦断図（予定ルートの縦断図と重ねる）
- 書き出し: GeoJSON（P1 で GPX も）

### 6.4 とんぼ返り（`tracback.ts`）
1. 記録した足あとを逆順にする
2. 線を単純化する（Douglas–Peucker 法。許容幅 = max(5 m, その区間の誤差)）
3. 進む向きが 30° 以上変わる点を「曲がり角」にする
4. 各曲がり角に、300 m 以内で最も近い目印を付けて案内文を作る（例: 「方位 230° へ 120 m。目印B（丸いクレーター）を右手に見て進む」）
5. 案内は**テンプレートで作る**（生成 AI は使わない）
- 近道（P1）: 足あとの2点を直線で結ぶ道が、すべて「安全」「注意」のマスだけを通り、元の道より 30% 以上短い場合だけ提案する

### 6.5 「迷った」モード（`LostMode.tsx`）
1. **最後に確定した地点**（`src = 'fix'`）と、現在の誤差の円を表示する
2. **いちばん近い足あとの点**の方向と距離を表示する（確定した点を優先する）
3. 近くの目印を3つ示し、「どれが見えますか？」で位置を補正する（P1 の T-42。P0 は表示だけ）
4. **帰還の限界**: 基地までの残りの距離 ÷ 歩く速さ（初期値 0.4 m/s、UI で変更可）× 余裕 1.3 と、酸素・バッテリーの残り時間（シミュレーション）を比べ、「あと◯分以内に戻り始める必要がある」を表示する

### 6.6 通信遮断モード（`CommStatus.tsx`）
- ヘッダーに「通信可 / 圏外」と**未送信の件数**を表示する
- 圏外の間は記録を `sent = false` でためる。通信が戻ったら古い順に送る（デモでは送信済みに変えるだけ）
- P1: 基地のアンテナから地形データで見通しを計算し（`viewshed.png`）、**地図上の圏外の場所を塗る**。足あとが圏外に入ったら自動で圏外モードにする

### 6.7 火星の時刻（P1、`marsTime.ts`）
- NASA GISS の **Mars24** のアルゴリズム（Allison & McEwen 2000）で、地球の時刻 → 火星日（MSD）、火星の協定時（MTC）、地方平均太陽時（LMST）、太陽黄経（Ls）を計算する
- **単体テスト**: Mars24 の公式ページに載っている計算例と一致すること
- Sol 番号は Curiosity の Sol（着陸日を 0 とする数え方）で表示する
