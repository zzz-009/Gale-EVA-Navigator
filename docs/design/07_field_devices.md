## 1. 先に確認したいこと（本当にそれでいい？）

### 1.1 「衛星から位置が取れる」と、これまでの設計が食い違う
これまでの設計（02・03）は「**火星には GPS がない** → 推測航法で位置を決め、誤差の円を出す → 迷ったら来た道を戻る」が物語の中心でした。「衛星から常に緯度経度が取れる」とすると、**誤差の円も「迷った」もとんぼ返りも、必要性が弱くなります。**

**この設計での解決（両立させる）**:
- 衛星による測位は「**将来の火星の測位衛星を仮定したもの**」として扱い、画面にそう書く（現実には、火星に GPS のような測位衛星はまだない）
- **衛星が見えている間だけ**位置が確定する（誤差 5 m）。**通信遮断モード（圏外）の間は衛星の位置も届かない** → 推測航法に切り替わり、誤差の円が広がる
- つまり「衛星の位置 = 目印での確定と同じ扱い」。迷う場面と、とんぼ返りの物語はそのまま残る

### 1.2 健康状態のデータ
宇宙服の生体データの公開データはないので、**健康状態はシミュレーション**として表示し、そう明記する。危険の目安（閾値）も「仮の値」と書く。

### 1.3 3 つの画面の連携の範囲
- 同じパソコンの別のウィンドウ（タブ）どうしなら、ブラウザの機能（`BroadcastChannel`）で連携できる（サーバー不要）
- **別の端末どうし（スマホとパソコン）の連携は、サーバーが必要なのでやらない**。デモでは 1 台のパソコンで 3 つのウィンドウを並べる

### 1.4 時間
全部で約 9 時間。機能凍結までに入るが、余裕は少ない。**P0（V-2・V-3・V-1・V-5）を先に終わらせ、P1（V-4・V-6・V-7）は時間を見て判断する。**

## 3. V-2 目的地の点をドラッグで動かす

- 計画中だけ、目的地（紫の点）を**ドラッグ**できる（`L.marker({ draggable: true })`）。現場（記録中など）ではドラッグできない
- ドラッグを離したら:
  1. 離した地点が通行不可（傾斜 20° 超・危険エリア・地域の外）なら、**近くの通れる地点に寄せる**（`App.tsx` の `freeCell` と同じ考え方。30 マス以内に見つからなければ元の位置に戻し、「ここには置けません」と表示）
  2. その目的地でルートを計算し直す（今の `targets` の該当する目的地の座標を書き換える）
- 動かした目的地の名前は「目標A（移動済み）」のように分かるようにする
- 「元の位置に戻す」ボタンを右パネルに置く
- **完了条件**: ドラッグで目的地が動き、ルートが計算し直される。崖の上に置こうとすると近くの平らな場所に寄る

## 4. V-3 現在地から目的地までの距離

| 表示 | 計算 |
|---|---|
| 直線距離 | `haversine(現在地, 目的地)` |
| ルートに沿った残りの距離 | 予定ルートの線上で、現在地に最も近い点から目的地までの長さ |
| 方位 | `bearing(現在地, 目的地)`（北 = 0°）|
| 到着予定 | 残りの距離 ÷ 平地の歩く速さ（`walkSpeed(0)`）。「約 48 分」|

- 計画中は「基地から」、現場では「現在地から」の値を出す
- 表示場所: 右パネルの上と、ヘルメット表示（V-5）
- 予定ルートから外れているとき（30 m 以上）は、ルートに沿った距離ではなく直線距離を大きく出し、「ルートから外れています」と添える
- **完了条件**: 記録の再生中、距離が減っていく。目的地をドラッグすると値が変わる

## 5. V-1 位置の取得元と、現在地の点

### 5.1 位置の取得元を差し替えられるようにする
```ts
// app/src/position/source.ts（新規）
export type PositionFix = {
  t_utc: string; lat: number; lon: number;
  heading_deg?: number;            // なければ直前の点からの向き
  accuracy_m: number;              // 衛星の位置なら 5、推測航法なら誤差の円の半径
  source: 'satellite' | 'dead_reckoning' | 'simulation';
};
export interface PositionSource {
  start(onFix: (f: PositionFix) => void): void;
  stop(): void;
}
```
| 取得元 | 中身 | 優先 |
|---|---|---|
| `SimulationSource` | 今のシミュレーション（`sim.ts`）を包んだもの | P0（今の動きを保つ）|
| `JsonFeedSource` | **JSON ファイルの位置情報を時刻どおりに流す**（テスト用）。衛星から届いた位置という扱い | **P0** |

### 5.2 JSON の形式（テスト用の位置情報）
```json
{
  "format": "gale-eva-positions/1",
  "description": "テスト用の位置情報（衛星測位を仮定）",
  "positions": [
    { "t_utc": "2026-11-14T10:00:00Z", "lat": -4.69420, "lon": 137.37010, "accuracy_m": 5 },
    { "t_utc": "2026-11-14T10:00:30Z", "lat": -4.69445, "lon": 137.37052, "accuracy_m": 5 }
  ]
}
```
- 置き場所: `app/public/data/positions_test.json`（**基地から目標Aへの安全ルートに沿った点を 30 秒ごと**。Codex が `sim.ts` の足あとから作ってよい。座標は活動地域の中に入っていること）
- 読み込み方: ①起動時に上のファイル ②右パネルの「位置情報ファイルを読み込む」ボタンで、手元の JSON を選ぶ（`<input type="file">`。サーバー不要）
- 再生: ファイルの時刻の間隔 ÷ 再生速度で、順に `onFix` を呼ぶ
- **形式が違うファイルは読み込まず、何が違うかを表示する**（`format` の値、`positions` が配列か、各点に `lat`・`lon` が数値であるか、活動地域の中か）

### 5.3 通信遮断との関係（1.1 の解決）
- 通信可: 衛星の位置をそのまま使う（`source: 'satellite'`、誤差 5 m、足あとの点は `src: 'fix'`）
- **圏外: 衛星の位置は届かない**。最後の衛星の位置から推測航法で進め、誤差の円を広げる（`core` の `errRadius`）。足あとの点は `src: 'dr'`
- 圏外から戻ったら、次の衛星の位置で確定し直す（誤差が 5 m に戻る）

### 5.4 現在地の点（Google マップ風）
- 青い点 + **進む向きの扇形**（向きが分かる）+ 誤差の円
- 「現在地」ボタン（右下の ◎）を押すと、地図が現在地を追いかける（ドラッグしたら追いかけるのをやめる。Google マップと同じ）
- 位置が更新されるたびに、点をなめらかに動かす（0.3 秒で移動）

### 5.5 置き場所
`app/src/position/source.ts`、`simulationSource.ts`、`jsonFeedSource.ts`（すべて新規）。`App.tsx` は「どの取得元を使うか」と `onFix` で足あとに追加する部分だけ

### 5.6 完了条件
- テスト用の JSON で、現在地の点が動き、足あとが記録される
- 形式の違う JSON を読み込むと、理由が表示されて画面は壊れない
- 圏外にすると誤差の円が広がり、戻すと 5 m に戻る
- これまでのシミュレーション（迷う場面を含む）も、取得元を切り替えれば同じように動く

## 6. V-5 ヘルメット表示（HUD、スマートグラス風）

### 6.1 方針
- まずは**基地の画面の中で切り替える表示**として作る（地図の右上に「HUD 表示」ボタン）。押すと、画面全体が HUD のレイアウトになる。もう一度押すと戻る
- 別ウィンドウで開けるようにするのは V-6（P1）

### 6.2 表示するもの（文字は大きく、要素は少なく）
| 場所 | 中身 |
|---|---|
| 中央 | **周辺の地図だけ**（現在地を中心に半径約 300 m。**進む向きが上**。地図の操作は無効）。周辺の危険度・危険エリア・予定ルート・足あとを表示 |
| 上 | 目的地までの距離・方位・到着予定（V-3）。方位は「→ 63°」のような矢印付き |
| 左下 | 健康状態（V-4。on/off）|
| 右下 | 通信状態（通信可 / 圏外）、位置の取得元（衛星 / 推測）と誤差 |
| 下 | 警告を 1 行（ルートから外れている、砂嵐の接近、帰還の限界）|

- 背景は黒、文字は明るい緑系か白（ヘルメットのバイザーに映る想定）。**地図の画像は暗めに**（明るい地面の上でも文字が読めるように）
- 「進む向きが上」: 地図の回転は Leaflet の標準ではできないので、**地図を入れた箱を CSS の `transform: rotate(−向き)` で回し**、文字は回さない。向きが変わったら 0.3 秒かけて回す

### 6.3 完了条件
- 「HUD 表示」で切り替わり、記録の再生中、地図が向きに合わせて回り、距離が減っていく
- 両手がふさがっていても見るだけで分かる（ボタンを押さなくても、必要な情報がすべて出ている）

## 7. V-4 健康状態（シミュレーション、on/off）

| 項目 | 表示 | 仮の注意の目安 |
|---|---|---|
| 心拍数 | 92 bpm | 140 以上で注意 |
| 酸素の残り | 5 時間 18 分（今の値を使う）| 帰還の限界と連動 |
| 宇宙服の中の CO₂ | 0.4% | 1% 以上で注意 |
| 体温 | 36.8℃ | 38.0℃ 以上で注意 |
| バッテリー | 81%（今の値を使う）| 20% 以下で注意 |

- 値はシミュレーション（登りで心拍数が上がる、時間とともに少しずつ変わる）。**見出しに「健康状態（シミュレーション）」、目安に「仮の値」と書く**
- on/off: HUD の左下に表示。腕の端末（V-6）と、基地の画面の HUD 切り替えの近くにボタン
- 注意の目安を超えたら、HUD の下の警告に出す
- 置き場所: `app/src/health.ts`（値の計算）、表示は HUD の部品

## 8. V-7 全体図を「表示画面」として on/off

- 今の全体図（ミニマップ）の折りたたみを、「**全体図 on/off**」として扱いを分かりやすくする（ボタンの文言を「全体図を表示 / 隠す」にそろえる）
- HUD 表示中も、全体図を on にすると右上に小さく出せるようにする

## 9. V-6 腕の端末（別ウィンドウ）と 3 画面の連携（P1）

- URL に `?view=hud` を付けると HUD だけ、`?view=wrist` を付けると腕の端末だけを表示する
- 腕の端末: 幅 360 px 程度、大きなボタンだけ（HUD 表示 on/off、健康状態 on/off、全体図 on/off、迷った、来た道を戻る）と、目的地までの距離
- 連携: `BroadcastChannel('gale-eva')` で、基地の画面（状態を持つ側）と HUD・腕の端末の間で、状態とボタンの操作を送り合う。**同じパソコンの別ウィンドウだけ**（1.3）
- **完了条件**: 3 つのウィンドウを並べ、腕の端末で「健康状態 on」を押すと HUD に健康状態が出る
