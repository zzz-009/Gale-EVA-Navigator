## 2. 審査基準を満たしているか

| 基準 | 満たし方 | 根拠になる画面・データ | 判定 | 残る弱点と対策 |
|---|---|---|---|---|
| **impact** | 「GPS がない、地球に聞いても最大40分かかる、通信が途切れる」という火星特有の問題に、計画（01）・記録（02）・帰還（03）の一連の流れで答える | 発表の冒頭の問題提起、通信遮断モードのデモ | ◎ | 月や地球の極地・災害現場にも使える、と一言添える |
| **creativity** | ①カーナビの考え方（とんぼ返り、圏外の案内、帰還の限界）を火星に持ち込む ②**位置の不確かさ（誤差の円）を正直に見せる** ③通信遮断を前提にした設計 | 「迷った」モード、誤差の円 | ◎ | 参考サイトと見た目が似る → 本物の地図と、記録・とんぼ返りで差を付ける |
| **validity** | 本物の HiRISE の画像と地形データ、説明できる計算（A*、推測航法の誤差モデル、火星の半径での距離）、各設計書の検証項目 | 指標の説明パネル、検証結果のスライド | ◯ | **地形データの入手が未確認**（G0 で確認）。足あとはシミュレーションと明記 |
| **relevance** | 課題文の必須（地図・3種類以上のデータ・ルート・安全）をすべて P0 で満たす。Mars Trek・HiRISE・地質図・DONKI を使う | 3章の対応表 | ◎ | 3つ目のデータ（地質・熱）が取れなければ放射線（DONKI）で代用 |
| **presentation** | 「迷子になった宇宙飛行士を連れて帰る」という物語。Apollo 14 で宇宙飛行士が、目標の Cone クレーターの縁のすぐ近くまで来ていながら縁を見つけられなかった史実を導入に使える | 3分のデモ（01 → 02 → 03 の順）| ◎ | デモが通信や読み込みに左右されないよう、タイルを事前に保存 |

**結論: 5基準とも満たせる見込み。最大のリスクは validity の「地形データ」1点。**

### 4.1 アプリ全体の状態とモード

```ts
type Mode = 'plan' | 'traverse' | 'lost' | 'tracback';
//  plan     = ルートを計画する（01）
//  traverse = 歩いて記録する（02）
//  lost     = 迷った（03 の入口）
//  tracback = 来た道を戻る（03）

type AppState = {
  mode: Mode;
  view: { lat: number; lon: number; zoom: number };
  plan: { start?: LatLon; goal?: LatLon; via: LatLon[]; routes: Route[]; selected?: RouteId };   // 01
  track: { points: TrackPoint[]; recording: boolean; simSpeed: number };                         // 02
  explorer: { pos: LatLon; heading: number; err_m: number; lastFixId?: string };                 // 02・03
  comm: { online: boolean; forcedOffline: boolean; unsent: number };                             // 02
  consumables: { o2_min: number; battery_pct: number };                                         // 03（シミュレーション値）
};
```

```
plan ──[出発]──▶ traverse ──[迷った]──▶ lost ──[戻る]──▶ tracback ──[基地に到着]──▶ plan
                    ▲                                     │
                    └───────────[足あとに戻れた]────────────┘
```

## 5. 期限に間に合うか

### 5.1 工数の見積もり（P0）

| 区分 | タスク | 見積もり |
|---|---|---|
| 準備 | T-01, T-02 | 1.3 h |
| データ | T-10, T-11, T-14, T-12, T-13 | 5.5 h |
| 共通の画面 | T-20（簡素化）, T-21, T-22 | 3.5 h |
| 01 ルートの計画（P0 部分） | R-01〜R-04 | 4.0 h |
| 02 足あとの記録（P0 部分） | K-01〜K-04 | 3.5 h |
| 03 とんぼ返り（P0 部分） | B-01〜B-04 | 4.0 h |
| **合計** | | **約 21.8 h** |

**使える時間**: 14:40 〜 09:00 の機能凍結まで **約 18.3 時間**。**このままでは約 3.5 時間足りない。**

### 5.2 対策（これで間に合わせる）

| 対策 | 効果 |
|---|---|
| **データの作業と画面の作業を並行させる**（画面はダミーのデータで先に作る。データの契約は TODO 5章で固定済み）| 実質 3〜4 h 短縮 |
| 検索ボックス（T-23）を P1 に下げる（地点の移動は、目標・基地のリストのボタンで代用）| 1.5 h |
| ダッシュボードの枠（T-20）を簡素化（左のアイコン列なし、指標カード4枚と右パネルだけ）| 0.5 h |
| 01 の「3本の比較」は P0 では数値の表だけ。レーダーチャート・縦断図は P1 | 1.0 h |
| 高解像度の地形データが 17:00 に間に合わなければ、全球の地形データ（約 200 m）で先に進める | G0 の失敗で全体が止まらない |

→ **並行作業を前提に、P0 は 11/15 03:00 に終わる見込み。** 09:00 の機能凍結まで 6 時間を P1 と予備に使える。

### 5.3 ゲート
- **11/14 17:00 G0**: 地形データから、等高線と傾斜を HiRISE の地図に重ねて表示できたか
- **11/15 03:00 M2**: P0（01・02・03 の最低ライン）が通しで動くか
- **11/15 09:00**: 機能凍結

### 5.4 間に合わなくなったときに捨てる順番
1. P2（HUD、写真、Curiosity の実際の走行記録の再生）
2. 04（太陽・地球の時間帯）、オフライン保存（PWA）→ 「通信遮断モード」のスイッチだけ残す
3. 01 の「3本の比較」→ 安全なルート1本だけ
4. 03 の「近道」と「目印での補正」
5. **最後まで残すもの**: 地図・危険エリア・ルート1本・足あとの記録・とんぼ返り・通信遮断モード
