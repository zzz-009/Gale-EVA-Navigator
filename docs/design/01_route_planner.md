# 設計書 01 — EVA Route Planner（障害物を避けて目標まで行くルート）

> 優先: **P0（1本）/ P1（3本の比較）** / 全体像: [00_overview.md](00_overview.md)
> 課題文の該当箇所: 「障害物を避けて、科学目標を達成するために宇宙飛行士が移動するルートの地図」「宇宙服と装備による動きにくさ」「安全が最優先」

---

## 1. 目的
基地（居住モジュール）から科学目標まで、**危険エリアを避け、宇宙服で歩ける傾斜だけを通るルート**を自動で計算する。3本の候補（安全 / 最短 / 科学）を並べ、**なぜそのルートを選んだのか**を数値と文章で説明する。

## 2. 利用者と場面
| 利用者 | 場面 |
|---|---|
| 宇宙飛行士（居住モジュールの画面、タブレット）| 出発前に、今日のルートを確認する |
| 地上や基地の計画担当 | 複数の候補を比べ、科学チームと安全担当の折り合いを付ける |

## 5. 計算仕様

### 5.1 計算用のグリッド
- 活動する地域（約 3 km 四方）の地形データを **5 m 間隔**に間引く（HiRISE の地形データが 1〜2 m の場合）→ 約 600 × 600 マス
- 200 m の代用データしかない場合は、そのまま使い、「ルートは粗い」と画面に表示する
- 前処理で `elev.f32`、`slope.f32`、`aspect.f32`（斜面の向き）、`rough.f32`（起伏）、`nogo.u8`（通行不可）を出力する

### 5.2 通行不可
- 傾斜 > 20°（UI で 15〜25° の範囲で変更可）
- `hazard_zones.geojson` の `level = no_go` の多角形の中
- 地形データの値がないマス

### 5.3 歩く速さ（`lib/walkSpeed.ts`）
- 登山で使われる **Tobler の歩行速度の式**を、宇宙服向けに上限を下げて使う
  ```
  v(s) = v0 × exp( −3.5 × | s + 0.05 | )     s = 進む向きの勾配（tan。登りは正、下りは負）
  v0 = 0.45 m/s（初期値。UI で変更可）
  ```
- 平らな地面で約 0.38 m/s（約 1.4 km/h）、緩い下りで最大。**式と v0 を「指標の説明」パネルに表示する**
- 火星の重力（地球の約 0.38 倍）で歩きやすくなる効果は、宇宙服の重さや動きにくさと相殺されるとして入れない（そう明記する）

### 5.4 1歩あたりのコスト（8 方向、マス a → b）
```
d     = 地表に沿った距離（水平距離と高低差から）
t     = d / v(s)                                    # 所要時間（秒）
risk  = d × ( (slope_b / slope_max)² + rough_norm_b + 0.5 × cross_b )
sci   = d × ( 1 − science_b )
cost  = w_t × (t × v0) + w_r × risk + w_s × sci     # t × v0 で「メートル相当」にそろえる
```
- `cross_b` = 進む向きに対する横向きの傾き / slope_max（横転のしやすさ）
- `science_b` = **急な崖の縁（傾斜 15° 以上。地層がむき出しの露頭）までの距離**で決める: `exp(−距離 / 60 m)`。科学目標の近く（`exp(−距離 / 200 m)`）も高くし、大きい方を使う（2026-11-14 変更: 目標からの距離だけだと、科学ルートが他の2本とほぼ同じ道になったため）。地質図が使えれば、目標の地質単位の中を 1 にする（P1）
- **すべての項は 0 以上**（A* が正しく動く条件）
- ヒューリスティック（推定残りコスト） = 直線距離 × w_t（`t × v0 ≥ 水平距離` なので過大評価にならない）

| プリセット | w_t | w_r | w_s | P0 / P1 |
|---|---|---|---|---|
| **安全** | 0.3 | 1.0 | 0 | **P0** |
| 最短 | 1.0 | 0.1 | 0 | P1 |
| 科学 | 0.3 | 0.3 | 1.0 | P1 |

### 5.5 ルートの指標
| 指標 | 定義 |
|---|---|
| 距離 | 地表に沿った距離の合計（平面の距離も併記）|
| 累積の登り・下り | 標高の増減の合計 |
| 最大傾斜 / 最大の横向きの傾斜 | ルート上の最大値 |
| 所要時間 | 5.3 の速さで歩いた時間の合計 × 1.0（休憩・作業時間は別に入力）|
| 危険エリアに近い区間 | 「制限」（15〜20°）のエリアの中を通る長さ |
| **EVA 安全スコア**（参考サイトの指標カード）| `100 − 40 × (制限エリアの中の長さ / 全長) − 30 × (最大傾斜 / slope_max) − 20 × (所要時間 / 活動の上限時間) − 10 × (圏外の長さ / 全長)`。0〜100 に収める。**式をマウスを乗せると表示** |

### 5.6 選んだ理由の説明（`lib/explain.ts`）— テンプレート。生成 AI は使わない
- ルート単位（P0）: 「◯◯を避けるため、最短より ◯ m 長いが、最大傾斜が ◯° → ◯° に下がる」
- 3本の比較（P1）: 推奨ルートと他の2本の差（距離・時間・最大傾斜・危険エリア・科学地点の数）
- 区間単位（P1）: 500 m ごとの区間で、コストの内訳の最大の項と、しきい値に近い値（「傾斜 16°（上限の 80%）」）

### 5.7 計算の実行場所
- A* は **Web Worker**（画面を固まらせない別の処理）で実行する
- ルートのジグザグ（8 方向の格子による）は、見通しの効く点を飛ばして直線にする「線の引き直し」で整える（P1。整えた後の線が通行不可を通らないことを確認する）

## 6. 型

```ts
type RoutePreset = 'safe' | 'short' | 'science';
type Route = {
  id: string; preset: RoutePreset;
  coords: [number, number][];                  // [lat, lon]
  surface_m: number; planar_m: number; ascent_m: number; descent_m: number;
  max_slope_deg: number; max_cross_deg: number; est_time_s: number;
  limited_zone_m: number; comm_out_m?: number; safety_score: number;
  explanation: string[];
  segments: { from: number; to: number; slope_deg: number; reason?: string }[];
};
```

## 7. 検証
| 確認すること | 期待される結果 |
|---|---|
| 平らな格子 | 出発地と目的地を結ぶ直線（に近い線）になる |
| 壁（通行不可）を置く | 壁を迂回する。通れない場合は「ルートなし」と表示する |
| A* とダイクストラ法 | 小さな格子で、同じコストの結果になる（ヒューリスティックが正しい）|
| 危険エリア | 実際の地形で、通行不可のマスを1つも通らない |
| 距離 | 縮尺バーで測った距離と、ルートの平面の距離がおおむね一致 |
