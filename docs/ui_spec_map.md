# 地図画面 UI 仕様（Google マップ風）— Codex 向け

> 作成: Claude Code / 実装: Codex
> 参照する地図: [JPL Mars Trek（Curiosity 周辺の HiRISE モザイク）](https://trek.nasa.gov/mars/#v=0.1&x=51.49837449544208&y=-11.577912176935094&z=2&p=urn%3Aogc%3Adef%3Acrs%3AEPSG%3A%3A104905&d=&l=curiosity_hirise_mosaic%2Ctrue%2C1&locale=&b=mars&e=-28.745764632718497%2C-72.9255672825825%2C131.74251362360266%2C49.76974292871232&sfz=&w=)
> **注意**: この地図は**火星（Gale クレーター）**です。Case 11 は月の課題なので、この地図で作るなら課題は **Case 10（火星の地表探査の地図）** になります。実装は「天体の設定ファイル」を差し替えれば月にも使えるように作ります（7章）。

## 2. 技術選定

| 項目 | 採用 | 理由 |
|---|---|---|
| 地図ライブラリ | **Leaflet 1.9** | ズーム 0 が「横 2 × 縦 1」のタイル配置は、Leaflet 標準の `L.CRS.EPSG4326` とそのまま一致する |
| 座標系 | `L.CRS.EPSG4326` を拡張した **火星用の座標系**（下記） | 標準のままだと、距離と縮尺が**地球の半径**で計算されてしまう |
| UI | React + TypeScript（既存の構成）、地図部分は `react-leaflet` を使わず Leaflet を直接使う（細かい制御のため） | |

```ts
// 火星用の座標系: 経緯度の配置は EPSG4326 と同じ、距離だけ火星の半径で計算する
const MARS_R = 3396190; // m（火星の赤道半径）
export const CRS_MARS = L.extend({}, L.CRS.EPSG4326, {
  R: MARS_R,
  distance: L.CRS.Earth.distance, // R を使う計算式（大円距離）をそのまま流用
});
```
**完了条件**: 縮尺バーと距離の測定が、火星の値になっていること（経度 1° が赤道で約 59.3 km。地球なら約 111 km なので、ここで取り違えると一目でわかる）。

## 3. 画面の構成（v2: 参考サイトに合わせて更新）

> 参考: https://mars-saferoute-ai.vercel.app/ （2026-11-14 に確認。管制室風の暗い画面のダッシュボード。地形は**合成データのモック**で、地図の操作はできない）
> **方針**: 参考サイトの「レイアウトと見た目」を取り入れ、中身は**本物の NASA データ**（Mars Trek の HiRISE タイル、地形データ）と、Google マップ風に操作できる地図にする。**ここが参考サイトとの差別化になる。**
> 参考サイトの名前やロゴはそのまま使わない（別のチームの作品の可能性があるため）。

### 3.0 参考サイトの要素と、このアプリでの扱い

| 参考サイトの要素 | このアプリでの扱い | データ |
|---|---|---|
| 上部のヘッダー（ロゴ、状態表示、Sol と時刻） | そのまま採用。状態表示は「実データ: HiRISE」「宇宙天気: 静穏」、時計は **Sol・LMST（火星の地方平均太陽時）** | Mars24 の計算方法、DONKI |
| 左のアイコン列 | 採用（地図 / レイヤー / ルート比較 / 設定） | — |
| 4つの指標カード（EVA 安全スコア、移動距離、所要時間、科学観測ポイント） | 採用。**スコアの計算式をマウスを乗せると表示**する。距離は「地表に沿った距離」 | 地形データから計算 |
| 地図のカード（地形 / 斜面リスク / 熱環境 / 観測地点の切り替え） | **地図を本物にする**: Mars Trek の HiRISE タイル + Google マップ風の操作（4章の R1〜R10）。切り替えボタンは地図の右上 | Mars Trek、地形データ、地質図 |
| 地図の「＋」「−」「現在地」 | 採用（右下、4章の R6・R7） | — |
| 右のパネル: ルート候補の比較（安全優先 / 最短時間 / 科学探査） | 採用。カードを選ぶと、地図のルートと指標カードが切り替わる | A* の計算結果 |
| 環境リスクの内訳（傾斜・砂地・通信）の棒グラフ | 採用し、**宇宙天気（放射線）**を1本足す | 地形データ、DONKI |
| 「AI ROUTE ADVISOR」の文章 | 採用するが、名前は「**ルートの解説**」にする。**計算結果からテンプレートで作る文章**で、生成 AI ではない（そう明記する） | explain.ts |
| 経由地点のリスト（4地点） | 採用。クリックすると地図がその地点へ移動する | — |
| 「SYNTHETIC DATA / NOT FOR NAVIGATION」の表示 | 置き換え: 「画像: NASA/JPL/University of Arizona（HiRISE）。傾斜・所要時間は推定値」 | — |
| ミッション準備度 | 採用。定義（チェックリストの達成率）を表示する | — |

- **[⛶全画面] ボタン**: 指標カードと右パネルを隠し、**地図だけを画面いっぱいに表示**する（最初の要望「画面全体に地図」をこのモードで満たす）。もう一度押すと元に戻る
- 地図のカードは `height: calc(100vh − ヘッダー − タイトル行 − 指標カード)`。地図だけがスクロールせずに画面に収まるようにする

### 3.2 タブレット（768〜1279 px）
- 右パネルを幅 320 px にし、閉じるボタンを付ける（閉じると地図が広がる）

### 3.3 スマホ（768 px 未満）— 参考サイトのスマホ表示を確認済み
- ヘッダーはロゴ・画面名・状態表示だけ。指標カードは 2 × 2
- 地図は画面の高さの 60%
- 右パネルの中身は、地図の下に**タブ（ルート / リスク / 経由地）**で並べる
- 情報ウィンドウは下から出るパネルにする

### 3.4 見た目（デザインの決まり）
- 暗い背景の管制室風。色は CSS の変数にまとめる（`--bg`、`--panel`、`--border`、`--text`、`--muted`）
- 色の意味を固定する: **選択中のルート = 青緑**、**危険 = オレンジ**、**科学観測地点 = 紫**、**通信 = 青**
- 数値は等幅の数字（`font-variant-numeric: tabular-nums`）で、値が変わってもガタつかないようにする

### 3.5 地図の切り替えボタンの中身（参考サイトの4つ）

| ボタン | 中身 | データ（未確認のものは実装前に確認） |
|---|---|---|
| 地形 | HiRISE の画像 / 陰影付きの標高 | Mars Trek（✅確認済み）、地形データ（⚠） |
| 斜面リスク | 傾斜の4段階の色分け | 地形データから計算（⚠ データの入手先） |
| 熱環境 | 地表の温まりやすさ・冷えやすさ（熱慣性） | THEMIS などの熱のデータ（⚠ Mars Trek にあるか未確認。なければこのボタンは出さない） |
| 観測地点 | 科学的に価値のある地点、地質の単位 | USGS の地質図、Curiosity の調査地点（⚠） |

### 3.6 斜面リスクの表示（参考サイトの見た目 + 実際の地形データ）

**参考サイトで確認したこと**（2026-11-14、画面の SVG を調べて確認）
- 「斜面リスク」ボタンを押すと、**危険なエリアが丸みのある多角形**で表示される（ボタンを切るとすべて消える）
- 中身は手で描いた2つの図形（「STEEP SLOPE」と「SAND / DUNES」）で、**地形データとは関係ない**
- 見た目:

| エリア | 塗りの色 | 塗りの不透明度 | 縁取りの色 | 縁取りの不透明度 | 点線 |
|---|---|---|---|---|---|
| 急斜面（STEEP SLOPE） | `#ef7f62` | 0.15 | `#e89474` | 0.7 | 7 px 線 + 5 px すき間 |
| 砂地・砂丘（SAND / DUNES） | `#ec9f66` | 0.17 | `#eab479` | 0.65 | 8 px 線 + 5 px すき間 |

- エリアの中央に、小さい大文字のラベル。凡例には「危険エリア」の色見本

**このアプリでの作り方**: 見た目は参考サイトに合わせ、**形は実際の地形データの傾斜から自動で作る**。ここが参考サイトとの差別化になる。

#### 急斜面のエリア（P0）— 前処理 `build_hazard_zones.py`
1. 傾斜のグリッドから、2段階のエリアを取り出す: **通行不可**（20° 超）と**制限**（15〜20°）
2. 小さな点々を消す: ぼかし（ガウシアン、半径 約 2 マス）→ 細かい凸凹を消す処理（モルフォロジーの opening）→ **面積 2,000 m² 未満のエリアは捨てる**
3. 輪郭を多角形にする（`rasterio.features.shapes`）
4. 角を減らす（Douglas–Peucker 法、許容幅 3〜5 m）→ 角を丸める（Chaikin 法を2回）→ 参考サイトのような丸い形になる
5. 緯度経度の GeoJSON に書き出す: `hazard_zones.geojson`

```json
{ "type": "Feature",
  "properties": { "kind": "steep", "level": "no_go", "max_slope_deg": 27.4,
                  "mean_slope_deg": 22.1, "area_m2": 4100, "label": "急斜面 20°超" },
  "geometry": { "type": "Polygon", "coordinates": [ ... ] } }
```

#### 砂地・砂丘のエリア（P1）
- 傾斜からは判別できない。**USGS の地質図に砂丘の単位があればそれを使う**。なければ、HiRISE の画像を見て**手で1〜3か所を囲み**、`"source": "HiRISE の画像から手で判読"` と属性に書き、情報ウィンドウにもそう表示する（自動で検出したように見せない）

#### 表示の決まり（フロント）
| 項目 | 仕様 |
|---|---|
| 描き方 | `L.geoJSON` の多角形。スタイルは上の表の値（`fillOpacity`、`dashArray: '7 5'` など）|
| 段階の違い | 通行不可 = 上の表の急斜面の色。制限（15〜20°）= 同じ色で塗りの不透明度 0.08、点線だけ（薄く見せる）|
| ラベル | 面積が画面上で十分大きいときだけ、エリアの中央に「急斜面 20°超」「砂丘」を表示（`L.tooltip` を `permanent` で）。ズームを引いたら隠す |
| HiRISE の上での見やすさ | HiRISE の画像は明るい所があり、不透明度 0.15 だと見えにくい場合がある。**実物の画像の上で確認し、必要なら塗りを 0.22 まで上げる**。レイヤーパネルに不透明度のスライダーを付ける（P1）|
| マウスを乗せる / タップ | 「急斜面 最大 27° / 平均 22° / 面積 0.41 ha」と、ルートがこのエリアを避けているか |
| ルートとの関係 | ルートがエリアを通る区間は、ルートの線を赤い点線にする。右パネルの「環境リスクの内訳」の「最大傾斜の危険度」= ルートの長さのうち、エリアの中を通る割合 |
| 凡例 | 「危険エリア（急斜面）」「危険エリア（砂丘）」の色見本 |
| ボタン | 地図の右上の「斜面リスク」ボタンで、すべての危険エリアを表示 / 非表示 |

## 4. 要件ごとの仕様と完了条件

| # | 要件 | 仕様 | 完了条件 |
|---|---|---|---|
| R1 | 画面全体に地図 | 地図の要素を `position: absolute; inset: 0`。他の UI はすべて地図の上に浮かぶカード | ウィンドウの大きさを変えても余白やスクロールバーが出ない |
| R2 | 左上に検索ボックス | 上・左から 12 px、幅 360 px（スマホは左右 12 px で全幅）。入力中に候補を最大 8 件表示 | ↑↓ キーで候補を選び、Enter で決定できる |
| R3 | 検索すると地点へ移動 | 検索対象: ①地名（Gale 周辺の地名・Curiosity の調査地点）②**座標**（`-4.59, 137.44`、`4.59S 137.44E` の両方の書き方）。決定すると `map.flyTo(座標, ズーム 15)` で移動し、マーカーを置いて情報ウィンドウを開く | 地名と座標の両方で移動できる。見つからないときは「見つかりません。座標でも検索できます（例: -4.59, 137.44）」を表示 |
| R4 | ホイールでズーム | Leaflet 標準（`scrollWheelZoom: true`）。ズーム範囲 0〜16 | 16 より拡大しない。範囲外は背景のタイルが表示される |
| R5 | ドラッグで移動 | Leaflet 標準。経度方向は世界をくり返さない（`noWrap: true`、`maxBounds` を設定） | 地図の端の外に大きくはみ出さない |
| R6 | 現在地ボタン | **ブラウザの位置情報（GPS）は使わない**（地球上の位置になってしまうため）。「現在地」= **探査者（宇宙飛行士・ローバー）の位置**。デモではシミュレーションした位置を使い、ナビ中は位置が動く。押すとその位置へ移動し、青い点 + 向きの扇形を表示。もう一度押すと「追従モード」（地図が探査者の位置を追いかける） | 押すと探査者の位置へ移動する。追従モードの ON/OFF がボタンの見た目でわかる |
| R7 | 右下にズームボタン | Leaflet 標準の左上のズームボタンは消し（`zoomControl: false`）、右下に `L.control.zoom({ position: 'bottomright' })` を置く。現在地ボタンはその上 | パソコンで右下に「＋」「−」と現在地ボタンが縦に並ぶ |
| R8 | クリックでマーカー | パソコン: **クリック**でマーカーを置く。スマホ: **長押し（0.5 秒）**で置く（ドラッグ中に誤って置かないため。Google マップと同じ）。仮のマーカーは1つだけで、置き直すと前のものは消える。情報ウィンドウの「保存」で残せる | 地図のドラッグ後にマーカーが置かれない（`click` と `dragend` を区別する） |
| R9 | マーカーをクリックで情報ウィンドウ | パソコン: マーカーの上に吹き出し（`L.popup`）。スマホ: 下から出るパネル。中身は 5 章 | 吹き出しが画面の端で切れない（`autoPan: true`） |
| R10 | レスポンシブ対応 | 区切りは 768 px。スマホでは時計バーとレイヤーボタンをアイコンだけにする。ボタンは 44 px 以上の大きさ（指で押しやすくする） | 375 px 幅（iPhone SE 程度）と 1440 px 幅で崩れない |

### 追加の標準部品
- **縮尺バー**（左下）: 火星の座標系で計算する（2章）
- **座標の表示**（下中央）: マウスの位置の緯度・経度（スマホは地図の中心）
- **出典の表示**（右下）: 「Mars Trek: NASA/JPL-Caltech」「HiRISE: NASA/JPL/University of Arizona」。**必ず表示する**
- **レイヤーボタン**（左下）: 背景の切り替え（HiRISE / Viking / 陰影付きの標高）+ 重ねる情報（傾斜・地質・ルート）

```

└──────────────────────────────┘
```
- **標高・傾斜・地質は、事前計算した範囲の中だけ表示**し、範囲外は「この範囲は計算対象外です」と表示する（嘘の値を出さない）
- 値の出典（DEM・地質図の名前）をウィンドウの下に小さく表示する

## 6. 状態管理と URL

- 地図の中心・ズーム・マーカーを URL に入れる（例: `#lat=-4.5895&lon=137.4417&z=15&m=-4.5895,137.4417`）→ **発表のデモで同じ画面をすぐ開ける**、共有もできる
- 状態は1つのストア（React の `useReducer` で十分）にまとめる: `view`、`tempMarker`、`savedMarkers[]`、`explorer`（現在地）、`followMode`、`activeLayers[]`
